## 1. 文档概述

### 1.1 背景

MiniMe-core 当前已具备基础的代码编辑能力（语法高亮、查看/编辑切换、Markdown 高亮引擎）。在保持轻量的前提下，编辑器还可以在以下几个方向做体验提升：代码片段、多光标编辑、性能优化、主题个性化、字体排版。

这些方向的共同特点是：**不依赖容器环境、不引入重型服务、纯客户端实现、对现有架构侵入小**。

### 1.2 扩展方向总览

| 方向 | 子项 | 优先级 |
|------|------|--------|
| **编辑效率** | 代码片段（Snippets） | P1 |
| | 多光标编辑 | P3 |
| **性能优化** | 内存优化 | P2 |
| | 启动速度优化 | P2 |
| **外观个性化** | 更多主题与自定义 | P2 |
| | 字体与排版 | P2 |

## 2. 代码片段（Snippets）

### 2.1 功能描述

内置常用代码片段，用户输入触发词后按空格（或特定按键）自动展开成完整的代码结构，支持占位符跳转。

### 2.2 内置片段分类

| 语言 | 片段示例 | 触发词 |
|------|---------|--------|
| Python | for 循环、函数定义、类定义、if-else、try-except、with 语句、列表推导式 | `for`、`def`、`class`、`if`、`try`、`with` |
| JavaScript | for 循环、函数、箭头函数、类、if-else、try-catch、Promise、async/await | `for`、`function`、`=>`、`class`、`try`、`promise`、`async` |
| TypeScript | 接口、类型定义、泛型函数、枚举 | `interface`、`type`、`func`、`enum` |
| Java | 类、方法、main 方法、for 循环、try-catch、System.out.println | `class`、`method`、`main`、`for`、`sout` |
| Go | 函数、结构体、方法、for 循环、if-else、错误处理、goroutine | `func`、`struct`、`method`、`for`、`err`、`go` |
| Rust | 函数、结构体、impl、match、for 循环、Result 处理 | `fn`、`struct`、`impl`、`match`、`for` |
| C/C++ | 函数、类、for 循环、if-else、#include、main 函数 | `func`、`class`、`for`、`include`、`main` |
| HTML | 文档结构、div、table、form、img、a、列表 | `html`、`div`、`table`、`form` |
| CSS | 弹性布局、网格布局、居中、动画、媒体查询 | `flex`、`grid`、`center`、`animate`、`media` |
| JSON | 基本结构、数组、嵌套对象 | `{}`、`[]` |
| Markdown | 标题、表格、代码块、列表、链接、图片 | `#`、`table`、`code`、`list`、`link` |
| SQL | SELECT、INSERT、UPDATE、DELETE、JOIN、CREATE TABLE | `select`、`insert`、`update`、`join`、`create` |
| Shell | for 循环、if-else、函数、case | `for`、`if`、`func`、`case` |
| Docker | Dockerfile 基本结构、COPY、RUN、EXPOSE、ENTRYPOINT | `docker`、`copy`、`run` |
| Git | 常用命令组合 | `commit`、`branch`、`rebase` |

### 2.3 片段格式

```json
{
  "name": "Python for 循环",
  "prefix": "for",
  "language": "python",
  "description": "for 循环基本结构",
  "body": [
    "for ${1:item} in ${2:iterable}:",
    "    ${0:# TODO: 循环体}"
  ]
}
```

**占位符语法**：
- `${1:默认值}`：编号占位符，按 Tab 跳转到下一个
- `${0}`：最终光标位置（最后一个 Tab 跳到这里）
- `${1|选项1,选项2,选项3|}`：多选占位符，展开后显示选项列表
- `$TM_FILENAME`：变量，替换为当前文件名
- `$TM_CURRENT_LINE`：变量，替换为当前行内容

### 2.4 UI/UX 设计

```
触发与展开流程：

1. 用户输入触发词（如 `for`）
2. 自动补全列表中显示匹配的片段（图标+名称+描述）
3. 用户选中片段（或按空格/回车）
4. 片段展开为完整代码结构
5. 第一个占位符高亮选中，用户输入替换
6. 按 Tab 跳转到下一个占位符
7. 所有占位符填写完成后，光标跳到 ${0} 位置

占位符视觉：
- 当前占位符：蓝色背景高亮
- 已填写的占位符：正常显示
- 多个相同编号的占位符：同步修改（修改一个，其他同步更新）

片段管理：
- 设置页面有"代码片段"管理入口
- 可以查看所有内置片段（按语言分类）
- 可以添加自定义片段（名称、触发词、语言、内容）
- 可以编辑/删除自定义片段
- 可以导入/导出片段（JSON 格式）
```

### 2.5 技术实现方案

**片段解析器**：
- 解析 JSON 格式的片段定义
- 解析占位符语法（${1:默认值}、${0}、变量等）
- 构建片段的 TabStop 列表（按编号排序的占位符位置）

**展开逻辑**：
- 将片段的 body 插入到编辑器当前位置
- 计算每个占位符在插入后的文档中的位置
- 选中第一个占位符
- 维护当前 TabStop 索引，按 Tab 时移动到下一个

**与自动补全的集成**：
- 片段作为自动补全的一个来源
- 触发词匹配时，片段和普通关键字一起显示在补全列表中
- 片段有特殊图标（如闪电图标），与普通补全区分

### 2.6 移动端适配

- **Tab 键替代**：移动端没有 Tab 键，用"键盘上方工具栏的→按钮"或"在占位符上点击"跳转
- **占位符触摸**：当前占位符高亮，用户可以直接点击其他占位符跳转
- **同步修改**：相同编号的占位符，修改一个时其他同步更新（实时显示）
- **片段选择**：补全列表中的片段项足够大，方便触摸选择

### 2.7 风险与挑战

| 风险 | 影响 | 应对 |
|------|------|------|
| 片段展开后占位符位置计算错误 | 光标定位错乱 | 充分测试边界情况（多行片段、嵌套占位符、特殊字符） |
| 与现有自动补全冲突 | 补全列表混乱 | 片段有特殊图标和分类，与普通补全区分；可以在设置中开关片段补全 |
| 自定义片段格式错误 | 展开失败 | 导入时校验格式；错误时提示具体哪一行有问题；提供片段模板 |
| 占位符同步修改性能差 | 输入卡顿 | 相同编号占位符数量限制（最多 10 个）；批量更新 |

### 2.8 预估工作量

- 片段数据（内置 100+ 片段，按语言分类）：3-4 天
- 片段解析器（JSON 解析+占位符解析）：2-3 天
- 展开逻辑（插入+占位符定位+Tab 跳转）：3-4 天
- 与自动补全集成：2 天
- 自定义片段管理（增删改查+导入导出）：2-3 天
- 移动端适配（Tab 替代+触摸跳转）：2 天
- 测试与优化：2 天
- **合计：16-20 天**

## 3. 多光标编辑

### 3.1 功能描述

支持同时在多个位置编辑，一次输入同时修改多个光标位置。包括添加光标、列选择、选中下一个相同词等。

### 3.2 功能列表

| 功能 | 说明 | 桌面端快捷键 | 移动端操作 |
|------|------|------------|-----------|
| 添加光标 | 在任意位置添加额外光标 | Alt+Click | 长按菜单"在下方添加光标" |
| 列选择 | 选择一块矩形区域 | Alt+Shift+Drag | 双指滑动选择 |
| 选中下一个 | 选中下一个相同的词 | Ctrl+D | 选中后点击"选中下一个"按钮 |
| 选中所有 | 选中所有相同的词 | Ctrl+Shift+L | 选中后点击"选中所有"按钮 |
| 上下添加光标 | 在当前行上下添加光标 | Ctrl+Alt+↑/↓ | 工具栏按钮 |
| 撤销光标 | 撤销最后一个添加的光标 | Ctrl+U | 工具栏按钮 |

### 3.3 UI/UX 设计

```
多光标编辑示例：

用户选中 "item"，点击"选中下一个"3 次：

    for item in items:
        ^^^^ ← 光标1
        total += item.price
                  ^^^^ ← 光标2
        print(item)
              ^^^^ ← 光标3

用户输入 "product"，三个位置同时修改：

    for product in items:
        total += product.price
        print(product)

多光标视觉：
- 每个光标都是一个独立的竖线光标，同步闪烁
- 多个光标位置的选区同时高亮
- 右上角显示"3 个光标"提示
- 工具栏显示多光标操作按钮（添加/撤销/选中下一个/选中所有/退出多光标）
- 按 Esc 退出多光标模式，只保留第一个光标
```

### 3.4 技术实现方案

**多光标数据结构**：

```kotlin
// 光标数据
data class Cursor(
    val id: String,
    var position: Position,      // 光标位置
    var selection: TextRange?,  // 选区（如果有）
)

// 多光标管理器
class MultiCursorManager {
    private val cursors = mutableListOf<Cursor>()
    private var primaryCursorIndex = 0  // 主光标（Esc 后保留的那个）

    fun addCursor(position: Position)
    fun addCursorAbove()     // 在主光标上方一行添加
    fun addCursorBelow()     // 在主光标下方一行添加
    fun selectNextMatch()    // 选中下一个相同的词
    fun selectAllMatches()   // 选中所有相同的词
    fun undoLastCursor()     // 撤销最后一个光标
    fun exitMultiCursor()    // 退出多光标模式，只保留主光标
    fun hasMultipleCursors(): Boolean

    // 文本操作：在所有光标位置同时执行
    fun insertText(text: String)
    fun deleteBackward()
    fun deleteForward()
    fun moveCursorsLeft()
    fun moveCursorsRight()
    fun moveCursorsUp()
    fun moveCursorsDown()
}
```

**列选择实现**：
- 记录选择起点和终点的行号和列号
- 对范围内的每一行，在对应列号位置创建光标
- 如果行长度不足，光标在行尾
- 列选择时输入，所有行同时插入

**选中下一个实现**：
- 获取当前选中的文本
- 从当前光标位置向后搜索下一个匹配
- 找到后创建新光标并选中匹配文本
- 找不到时提示"已到达文件末尾"

**文本操作同步**：
- 所有光标位置同时插入/删除文本
- 插入文本后，后面的光标位置需要偏移（因为前面插入了字符）
- 从后往前操作，避免位置偏移问题
- 如果两个光标位置重叠，合并为一个光标

### 3.5 移动端适配

- **添加光标的手势**：长按空白处，弹出菜单"在此处添加光标"
- **列选择手势**：双指同时按下并滑动，选择矩形区域（需要与缩放手势区分）
- **工具栏**：多光标模式时，键盘上方显示工具栏（添加光标/选中下一个/选中所有/撤销/退出）
- **光标可见性**：多个光标时，每个光标都显示，但主光标稍粗（区分）
- **性能**：光标数量限制（最多 100 个），超过时提示"光标过多"

### 3.6 风险与挑战

| 风险 | 影响 | 应对 |
|------|------|------|
| 多光标位置偏移计算错误 | 输入后光标位置错乱 | 从后往前操作；充分测试边界情况（行尾、空行、不同长度行） |
| 移动端手势冲突（列选择与缩放） | 用户误操作 | 明确手势区分（双指滑动=列选择，双指捏合=缩放）；提供按钮作为替代 |
| 光标过多导致性能问题 | 输入卡顿 | 限制最多 100 个光标；超过时提示；性能优化（批量操作） |
| 用户不理解多光标概念 | 功能闲置 | 首次使用时显示引导提示；工具栏按钮有文字说明 |
| 与 sora-editor 的单光标模型冲突 | 实现复杂 | 深入研究 sora-editor 的光标 API；可能需要扩展或自定义光标管理 |

### 3.7 预估工作量

- 多光标管理器（数据结构+文本操作同步）：4-5 天
- 添加光标/上下光标/撤销光标：2-3 天
- 选中下一个/选中所有：2-3 天
- 列选择：3-4 天
- 多光标渲染（多个光标+选区同步）：3-4 天
- 移动端适配（手势+工具栏）：3-4 天
- 与 sora-editor 集成调试：3-4 天
- 测试与优化：3-4 天
- **合计：23-31 天**

## 4. 内存优化

### 4.1 优化策略

| 策略 | 说明 |
|------|------|
| 高亮缓存 LRU | 着色缓存使用 LRU 策略，超过上限时回收最久未使用的 |
| 离屏内容回收 | 滚出可视区域的行，渲染资源立即回收 |
| 内存监控 | 监控应用内存使用，接近上限时主动释放资源并提示用户 |
| 文件关闭清理 | 关闭文件时，及时释放该文件的所有缓存（AST/着色/文档） |
| 图片懒加载 | Markdown 中的图片只在可视区域时加载，离屏的不加载 |
| 语法缓存回收 | 非当前文件语言的语法定义从内存释放，需要时重新加载 |
| 主题缓存优化 | 切换主题后，旧主题的颜色映射缓存及时释放 |

### 4.2 内存预算

| 组件 | 预算（1MB 文件） | 预算（10MB 文件） |
|------|-----------------|------------------|
| 文档内容 | 2MB | 20MB |
| AST/语法树 | 5MB | 30MB |
| 着色缓存 | 3MB | 15MB |
| 渲染资源 | 2MB | 5MB |
| 其他 | 3MB | 10MB |
| **合计** | **15MB** | **80MB** |

### 4.3 关键实现点

**LRU 缓存设计**：
- 基于 LinkedHashMap 实现 LRU 缓存
- 缓存上限可配置（默认：行级缓存 5000 条，块级缓存 1000 条）
- 缓存满时，自动删除最久未使用的条目
- 提供缓存命中率统计，用于调优

**离屏内容回收**：
- 监听滚动事件，当行滚出可视区域（含预渲染缓冲区）时，回收该行的渲染资源
- 回收内容：Span 列表、绘制缓存、行高计算结果
- 行重新进入可视区域时，按需重新计算
- 回收时机：滚动停止后 200ms 执行（避免滚动过程中频繁回收/重建）

**内存监控与主动释放**：
- 注册 Application 的 onTrimMemory 回调
- 内存等级达到 TRIM_MEMORY_RUNNING_LOW 时，主动释放非必要缓存：
  - 清除所有着色缓存（可视区域除外）
  - 释放非当前文件的语法定义
  - 减少预渲染缓冲区大小
- 内存等级达到 TRIM_MEMORY_RUNNING_CRITICAL 时，进一步释放：
  - 关闭行内代码高亮缓存
  - 释放所有离屏内容
  - 提示用户"内存不足，部分功能已降级"

**文件关闭清理**：
- 关闭文件时，调用专门的清理方法：
  - 取消所有未完成的解析/着色任务
  - 清除该文件的所有缓存（AST、着色、行高）
  - 释放文档内容引用
  - 通知 GC 回收
- 确保没有内存泄漏（监听器、回调、定时器全部注销）

### 4.4 预估工作量

- LRU 缓存实现 + 命中率统计：2-3 天
- 离屏内容回收机制：2-3 天
- 内存监控 + 主动释放策略：2-3 天
- 文件关闭清理 + 泄漏排查：2 天
- 图片懒加载（Markdown）：1-2 天
- 内存测试与调优：2-3 天
- **合计：11-16 天**

## 5. 启动速度优化

### 5.1 优化策略

| 策略 | 说明 |
|------|------|
| 编辑器懒加载 | 打开文件时才初始化编辑器组件，应用启动时不初始化 |
| 语法懒加载 | 只加载当前文件需要的语言语法，其他语言按需加载 |
| 主题预加载 | 启动时预加载当前主题的颜色映射，避免切换时卡顿 |
| 首屏优先 | 打开文件时，先渲染可视区域，后台继续解析和高亮其他部分 |
| 缓存预热 | 上次打开的文件，缓存其 AST 和着色结果，下次打开时直接使用 |
| 异步初始化 | 非核心功能（自定义片段、额外主题）异步初始化，不阻塞编辑器启动 |

### 5.2 性能目标

| 指标 | 目标 |
|------|------|
| 应用启动到编辑器可用 | < 1 秒 |
| 打开小文件（< 100KB）到首屏显示 | < 200ms |
| 打开大文件（10MB）到首屏显示 | < 500ms |
| 切换主题到显示完成 | < 100ms |

### 5.3 关键实现点

**编辑器懒加载**：
- 应用启动时，只初始化应用框架和首页
- 编辑器组件（sora-editor 的 CodeEditor、TextMate 环境等）在用户第一次打开文件时才初始化
- 初始化过程显示加载动画
- 初始化完成后缓存实例，后续打开文件复用

**语法懒加载**：
- 启动时只加载默认语言的语法（如 Markdown、Plain Text）
- 打开其他语言文件时，按需加载对应的 TextMate grammar
- 语法加载异步执行，加载完成前先用基础高亮（关键字匹配）
- 已加载的语法缓存，下次打开同语言文件直接使用

**首屏优先渲染**：
- 打开文件时，先读取可视区域的内容（前 N 行）
- 可视区域优先解析和高亮，立即显示
- 其他部分在后台线程异步解析和高亮
- 滚动到未高亮的区域时，如果还在解析中，显示加载占位
- 解析完成后，自动更新显示

**缓存预热**：
- 记录最近打开的文件列表（最多 10 个）
- 应用启动时，在后台线程预加载最近文件的语法和主题
- 用户打开最近文件时，直接使用预热的缓存，首屏显示更快
- 预热任务优先级低，不影响应用启动和当前操作

### 5.4 预估工作量

- 编辑器懒加载 + 语法懒加载：2-3 天
- 首屏优先渲染 + 后台异步解析：3-4 天
- 缓存预热（最近文件预加载）：2-3 天
- 主题预加载 + 异步初始化：1-2 天
- 性能测试与调优：2-3 天
- **合计：10-15 天**

- 导入的主题可以编辑和删除
- 导入的主题与内置主题同等对待（可以设为默认、可以预览）

### 6.3 自定义主题编辑器

- 可视化主题编辑器：
  - 选择基础主题（从内置主题中选一个作为起点）

- 支持导出主题（JSON 格式，分享给其他用户）
- 支持重置（恢复到基础主题的原始颜色）

- 主题预览：点击主题可以全屏预览（显示多种语言的代码示例）
- 主题搜索：主题较多时支持搜索
- 主题分类：按暗色/亮色/高对比度分类筛选
- 默认主题设置：可以设置默认主题（亮色模式和暗色模式分别设置）
- 跟随系统：可以设置主题跟随系统的深色/浅色模式

- 主题导入（VS Code/TextMate 格式解析+转换）：3-4 天
- 自定义主题编辑器（可视化调整+实时预览）：4-5 天

## 9. 风险与挑战汇总

### 9.1 技术风险

| 风险 | 影响范围 | 严重程度 | 应对策略 |
|------|---------|---------|---------|
| 多光标与 sora-editor 单光标模型冲突 | 多光标编辑 | 高 | 深入研究 sora-editor 光标 API；可能需要扩展或自定义；先做技术验证 |
| 片段展开后占位符位置计算错误 | 代码片段 | 中 | 充分测试边界情况；与 sora-editor 的选区 API 深度集成 |
| 内存优化导致功能异常 | 内存优化 | 中 | 渐进式回收；可视区域内容不回收；充分测试 |
| 主题导入格式不兼容 | 主题自定义 | 低 | 支持多种格式；导入失败时给出明确错误信息 |
| 连字渲染与语法高亮冲突 | 字体排版 | 低 | 测试连字字体在各种语法下的渲染效果；提供开关 |

### 9.2 移动端适配风险

| 风险 | 影响范围 | 严重程度 | 应对策略 |
|------|---------|---------|---------|
| 触摸操作精度低（多光标/列选择） | 多光标编辑 | 中 | 按钮足够大；手势与按钮双路径 |
| 没有物理键盘快捷键 | 所有快捷操作 | 中 | 工具栏按钮；手势替代；可配置快捷键 |
| 双指缩放字号与缩放手势冲突 | 字体排版 | 低 | 明确手势触发条件（编辑器内双指捏合=字号，其他地方=缩放） |
| 自定义主题编辑器在小屏幕操作困难 | 主题自定义 | 低 | 颜色选择器优化；常用颜色快捷选择；支持横屏操作 |

### 9.3 产品风险

| 风险 | 影响范围 | 严重程度 | 应对策略 |
|------|---------|---------|---------|
| 功能过多导致设置页面臃肿 | 整体 | 低 | 设置页面分类清晰；高级设置折叠；合理的默认值 |
| 用户学习成本高（多光标） | 多光标编辑 | 低 | 首次使用引导；简洁的工具栏说明 |
| 主题过多导致选择困难 | 主题自定义 | 低 | 主题分类筛选；推荐主题置顶；预览功能 |
| 维护成本高 | 长期 | 低 | 模块化设计；文档完善；自动化测试 |
