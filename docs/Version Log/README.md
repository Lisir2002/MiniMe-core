# Version Log

本目录存放 MiniMe-core 项目的所有版本日志，采用统一格式规范。

## 目录结构

```
Version Log/
├── CHANGELOG.md                    # 总版本日志（所有版本汇总，倒序排列）
├── MiniMe-core v-Logs/             # 主应用各版本独立日志
│   ├── MiniMe-core 0.0.0.1 Version Log.md
│   ├── MiniMe-core 0.0.0.2 Version Log.md
│   └── ...
└── MiniMe-Logs v-Logs/             # 附属应用（日志查看器）各版本独立日志
    ├── MiniMe-Logs 0.0.1 Version Log.md
    ├── MiniMe-Logs 0.0.2 Version Log.md
    └── ...
```

## 命名规范

- 文档命名：`{软件名} {版本号} Version Log.md`
- 示例：`MiniMe-core 0.0.0.17 Version Log.md`、`MiniMe-Logs 0.0.7 Version Log.md`
- Tag 命名：主应用 `v{版本号}`（如 `v0.0.0.17`），附属应用 `logviewer-v{版本号}`（如 `logviewer-v0.0.7`）

## 文档格式规范

每个版本日志文档必须严格遵循以下格式：

```markdown
# {软件名} {版本号} Version Log

> {版本简介，100字以内，说明本次更新的核心价值}

**发布日期**：YYYY-MM-DD

### 新功能

- {每条一个变更，单条不超过一行，描述用户可感知的功能}

### 改进

- {每条一个变更，描述体验优化、性能提升、样式调整等}

### 修复

- {每条一个变更，描述修复的问题及症状}

### 安全

- {每条一个变更，描述安全相关改进}

### 已知问题

- {如有，列出当前版本已知但未修复的问题；无则写"无"}
```

### 格式约束

1. **主标题**：第一行，`# {软件名} {版本号} Version Log`
2. **版本简介**：第二行，引用块格式（`>`），100字以内，利益优先、平实语言
3. **发布日期**：ISO 8601 格式（`YYYY-MM-DD`）
4. **分类顺序**：新功能 → 改进 → 修复 → 安全 → 已知问题，无内容的分类省略
5. **条目规范**：每条一个变更，单条不超过一行，描述症状而非代码实现细节
6. **禁止 emoji**：分类标题和正文保持纯文字，简洁专业
7. **破坏性变更**：用「注意」显著标注并说明用户需要做什么

## 发版流程

1. 代码变更完成并通过编译验证
2. 更新 `CHANGELOG.md`，在 `[Unreleased]` 下方添加新版本条目
3. 在对应软件的 `v-Logs/` 目录下创建独立版本日志文档
4. commit 并 push 到 main
5. 打 tag 触发云端 CI 构建
6. CI 构建成功后，更新 GitHub Release 标题和说明（与版本日志内容一致）
