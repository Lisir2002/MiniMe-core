# Changelog

本文件记录 MiniMe-core 的用户可见变更，采用用户面向格式（见 [AGENTS.md](./AGENTS.md#发版规范最高优先级--强制约束--发版前逐条核对)）。

> **2026-09-25 格式变更**：原「三层日志规约」（用户层/开发者层/大模型层）已废弃，现统一为**用户面向唯一格式**。
> 结构：版本标题 → 100字简介 → 新功能 → 改进 → 移除 → 修复 → 安全 → 已知问题。
> 写作铁律：利益优先、平实语言、每条一个变更、单条≤一行、描述症状而非代码。

- 最新版本置顶，倒序排列。
- 日期用 ISO 8601（`YYYY-MM-DD`）。
- **破坏性变更用「注意」显著标注并说明用户需要做什么。**
- **禁止使用 emoji**：分类标题和正文保持纯文字，简洁专业。

## [0.0.0.13] - 2026-09-24

> 主应用模型供应商设置全面升级版本：8维能力标签体系、供应商级连通性测试、采样参数实装、API Path 自定义、请求超时/重试、模型收藏置顶、供应商复制、故障转移，从"基础配置"升级为"专业级模型管理"。

### 新功能

- 模型能力标签从3维扩展为8维：识图、视频、语音、工具、思考、代码、结构化输出、上下文窗口，不支持的能力显示灰色"无XX"禁用态
- 模型行显示简短描述（如"多模态旗舰，快速均衡"、"深度推理与编码"），覆盖 GPT/Claude/DeepSeek/Qwen/Gemini/GLM/豆包/阶跃等主流模型
- 供应商级连通性测试：编辑页和添加页均支持一键"测试连接"，通过 GET /models 验证 API Key + 端点有效性，内联显示成功/失败原因
- 采样参数实装：Temperature（0-2 Slider，Anthropic 为 0-1）、Top P（0-1 Slider）、Max Tokens（数字输入），实际传递到所有适配器请求体
- API Path 显式配置：默认按供应商类型自动填充（OpenAI=/v1/chat/completions，Anthropic=v1/messages，Gemini=v1beta），可自定义修改
- 请求超时与重试次数配置：超时 5-120 秒，重试 0-5 次，非流式请求和流式首字节等待均生效
- 模型收藏置顶：⭐标记收藏模型，收藏的模型在列表顶部显示
- 供应商复制：列表项一键复制配置（名称加"副本"后缀），适合同平台多 Key 场景
- 供应商故障转移：配置备用供应商后，主供应商请求失败（429/500/超时/网络错误）时自动切换到备用供应商重试

### 改进

- 能力标签颜色统一使用 MaterialTheme 主题色，深色模式自动适配
- Temperature Slider 范围按供应商类型动态区分：Anthropic 0-1，OpenAI/Gemini 0-2，避免超出 API 合法范围导致 400 错误
- 非对话模型（嵌入/语音识别/图像生成等）的工具调用和结构化输出能力正确标记为不支持，不再一刀切默认支持
- 非流式请求（上下文压缩、识图摘要）使用配置的 requestTimeout，不再固定 120 秒

### 移除

- 移除能力标签硬编码 ARGB 颜色值，统一使用主题色令牌

### 修复

- Anthropic 供应商 Temperature 设置超过 1.0 导致 API 400 错误
- 代码和结构化输出能力标签在深色模式下颜色不协调

## [0.0.0.12] - 2026-09-23

> 日志系统全面升级版本：运行日志页面重构为专业日志查看器，支持等级筛选、文件选择、实时尾随、搜索高亮、横竖屏自适应；同时日志底层深度优化，写入性能大幅提升，新增 FATAL 等级、线程信息、格式版本头、敏感信息脱敏、实时统计等能力，为后续独立日志附属应用奠定基础。

### 新功能

- 运行日志页面重构为专业日志查看器：结构化日志行（时间戳+等级徽章+Tag+消息+堆栈折叠），长按复制全文/消息/时间戳/Tag，关键词搜索实时高亮并支持上一处/下一处跳转
- 等级筛选栏常驻显示各等级数量徽章：单击筛选该等级及以上，长按进入多选模式，再次点击折叠该等级所有行
- 文件选择支持快捷范围（今天/近3天/近7天/全部）与自定义日期范围，文件列表显示大小并可多选合并查看
- 实时尾随模式：新日志自动滚动到底部并绿色脉冲高亮，上滑自动暂停并显示「有 N 条新日志」浮动按钮，点击恢复尾随
- 横屏自适应：≥600dp 自动切换左右分栏（左侧列表+右侧详情），竖屏保持堆叠布局
- 日志等级新增 FATAL（致命错误），位于 ERROR 之上，用于标记不可恢复的严重故障
- 日志行新增线程信息 `[thread:name]`，便于排查多线程并发问题
- 日志文件新增格式版本头（`# MiniMe Log Format v1`），记录应用版本与进程 ID，为日志格式演进与兼容性检测提供依据
- 新增实时统计能力：各等级计数、各 Tag 计数，运行时可查询
- 新增耗时记录便捷方法 `timing(tag, label, durationMs)`

### 改进

- 日志写入性能优化：从每条日志单独 open/write/close 改为内存队列缓冲 + 常驻 BufferedWriter，按 64KB 或 500ms 批量 flush，大幅降低 IO 开销
- 文件滚动策略从「超限截断删除全部历史」改为非破坏性滚动（`log-date.txt → .1 → .2`），历史日志完整保留
- 日志导出从全量 readText 入内存改为 8KB 流式复制，避免大文件导出时 OOM
- 日志配置集中管理：日志级别、缓冲大小、文件上限、清理天数等统一由 LogConfig 管理，支持运行时覆盖
- 日志层接口抽象：新增 Logger 接口与 TestLogger 实现，便于单元测试与未来扩展输出目标（网络/数据库）

### 修复

- 修复日志文件超过 5MB 时全部历史被截断删除的问题，改为滚动保留
- 修复多线程并发写入日志时的锁竞争问题，改为单线程写入器串行化处理
- 修复日志导出大文件时可能 OOM 的问题，改为流式复制

### 安全

- 敏感信息统一脱敏：日志写入前自动检测并脱敏 API Key、Access Token、密码、Authorization 头、长 base64 媒体数据等，避免敏感信息泄露到日志文件
- 格式版本头为后续日志格式不兼容变更提供检测机制，附属应用可根据版本号判断是否需要升级

- 数据库全库加密支持（SQLCipher 4.5.4）：6 个物理库可选 AES-256 加密，默认明文，设置页一键开启后自动迁移全部存量数据。
