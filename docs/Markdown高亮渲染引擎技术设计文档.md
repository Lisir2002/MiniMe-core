## 核心设计决策（v1.1 确认）

| 决策项 | 决策内容 | 说明 |
|--------|---------|------|
| **高亮模式** | 语法符号淡化（灰色），内容高亮 | `#`/`**`/`>` 等符号用灰色，标题/粗体/链接等内容用高亮色 |
| **渲染模式** | 纯高亮，不渲染，保持源码模式 | 不把 `**粗体**` 渲染成粗体，保持源码可见，只上颜色 |
| **标题字号** | 标题与正文同字号，只靠颜色区分 | 不做字号递增，简化行高计算，提升性能 |
| **行内代码** | 行内代码必须做语法高亮 | `` `print("hello")` `` 内部代码按对应语言高亮，不是只有背景色 |
| **性能** | 性能专项设计，大文件优先 | 增量解析+虚拟滚动+多级缓存，10MB 文件必须流畅 |
| **主题** | 直接复用现有代码高亮主题 | 不做独立 Markdown 主题系统，颜色从代码主题的 Token 颜色映射 |
| **查看/编辑** | 天然统一，都是源码模式 | 查看和编辑用同一套高亮管线，只有只读/可编辑的交互差异 |

## 1. 文档概述

### 1.1 背景

MiniMe-core 的文件查看器和代码编辑器需要支持 Markdown 文档的语法高亮。当前存在以下问题：

- **Markdown 语法符号与正文同色**：`# 标题`、`**粗体**`、`> 引用` 等语法符号没有颜色区分，可读性差
- **代码块高亮质量低**：代码块内部高亮质量低于纯代码文件
- **行内代码无高亮**：`` `code` `` 行内代码只有背景色，无语法高亮
- **嵌套结构处理差**：粗体套链接、列表套代码块等嵌套场景容易高亮错乱
- **大文件性能差**：长 Markdown 文档实时高亮卡顿，滚动不流畅

### 1.2 目标

构建一套**自写的、高性能的、纯高亮的** Markdown 渲染引擎。

| 目标层级 | 具体目标 | 衡量标准 |
|---------|---------|---------|
| **功能目标** | 完整支持 CommonMark + GFM 语法高亮，语法符号淡化+内容高亮 | 30+ 语法元素全部正确高亮，嵌套正确 |
| **行内代码目标** | 行内代码做语法高亮，与代码块质量一致 | 行内代码高亮正确，语言自动检测 |
| **性能目标** | 大文件流畅高亮 | 10MB 文件首屏 < 500ms，滚动 60fps，输入延迟 < 16ms |
| **主题目标** | 与代码高亮主题统一 | 切换代码主题时 Markdown 自动跟随，风格协调 |
| **一致性目标** | 查看与编辑统一 | 切换模式无样式跳变，都是源码模式 |

### 1.3 范围

**包含**：
- Markdown 块级语法解析（标题/段落/列表/引用/代码块/表格/分隔线等）
- Markdown 行内语法解析（粗体/斜体/删除线/行内代码/链接/图片等）
- 语法符号淡化 + 内容高亮的着色策略
- 行内代码语法高亮（委托代码高亮引擎）
- 代码块语法高亮（委托代码高亮引擎）
- 增量解析和虚拟滚动性能优化
- 复用现有代码高亮主题

**不包含**：
- Markdown 渲染成 HTML/富文本（只做高亮，保持源码）
- 标题字号变化（同字号，只靠颜色）
- 独立的 Markdown 主题系统（复用代码主题）
- 所见即所得编辑（保持源码编辑模式）
- 数学公式/Mermaid 渲染（只做语法高亮，不做渲染）

### 1.4 术语表

| 术语 | 说明 |
|------|------|
| AST | 抽象语法树，解析器输出的树状结构 |
| Token | 词法单元，具有类型和位置的文本片段 |
| Scope | 语义作用域，点分路径表示的语法类型标识 |
| Block | 块级元素，占据整行或多行的语法结构 |
| Inline | 行内元素，段落内部的语法结构 |
| GFM | GitHub Flavored Markdown，GitHub 扩展的 Markdown 规范 |
| 虚拟滚动 | 只渲染可视区域内的行，离屏行不渲染 |
| 增量解析 | 用户修改文本时，只重新解析受影响的部分 |
| 语法符号淡化 | `#`/`**`/`>` 等 Markdown 标记符号用灰色（低对比度）显示 |
| 内容高亮 | 标题文本/粗体文本/链接等内容部分用高亮颜色显示 |

### 2.2 模块划分

| 模块 | 职责 | 核心类 |
|------|------|--------|
| **解析引擎** | Markdown 文本 → AST，支持增量解析 | `MarkdownParser`、`BlockParser`、`InlineParser`、`MarkdownAst` |
| **着色引擎** | AST → Span 列表（带颜色的文本片段），符号淡化+内容高亮 | `MarkdownColorizer`、`ScopeColorMapper` |
| **行内代码高亮** | 行内代码委托代码高亮引擎，语言自动检测 | `InlineCodeHighlighter` |
| **性能层** | 增量解析、虚拟滚动、缓存 | `IncrementalParser`、`VirtualScrollManager`、`ParseCache` |
| **渲染层** | Span → 绘制，查看/编辑统一 | `MarkdownRenderer`、`MarkdownSpan` |
| **集成层** | 与现有查看器/编辑器/代码高亮集成 | `MarkdownHighlighter`（对外门面） |

### 2.3 核心数据流

```
用户输入文本变化
    │
    ▼
增量解析器（只解析受影响的块）
    │
    ▼
AST 更新（标记脏节点）
    │
    ▼
着色引擎（遍历脏节点，查代码主题颜色映射，生成 Span）
    │  ├── 语法符号 → 灰色（淡化）
    │  ├── 内容部分 → 代码主题对应 Token 颜色
    │  └── 行内代码 → 委托代码高亮引擎生成 Span
    ▼
Span 缓存更新
    │
    ▼
虚拟滚动管理器（只请求可视区域的 Span）
    │
    ▼
渲染层（绘制 Span + 光标 + 选区）
    │
    ▼
屏幕显示
```

### 2.4 设计原则

1. **解析与渲染分离**：解析器只产出 AST，不关心颜色；渲染层只消费 Span
2. **纯高亮不渲染**：保持源码模式，语法符号可见，只上颜色，不做富文本渲染
3. **符号淡化+内容高亮**：语法符号用灰色，内容用高亮色，提升可读性
4. **主题复用**：颜色直接映射现有代码高亮主题的 Token 颜色，不做独立主题系统
5. **性能优先**：增量解析、虚拟滚动、多级缓存，大文件流畅是硬指标
6. **行内代码高亮**：行内代码与代码块同质量，委托代码高亮引擎
7. **不重复造轮子**：代码高亮委托现有引擎，只自写 Markdown 语法解析和着色映射

## 3. 解析引擎设计

### 3.1 AST 节点设计

#### 3.1.1 节点基类

```kotlin
sealed class MarkdownNode {
    abstract val type: String           // 节点类型
    abstract val startLine: Int        // 起始行（0-based）
    abstract val endLine: Int          // 结束行（含）
    abstract val startCol: Int         // 起始列（0-based）
    abstract val endCol: Int           // 结束列（不含）
    abstract val children: List<MarkdownNode>  // 子节点
    open val scope: String? = null     // 语义作用域（用于着色）
    open val isMarker: Boolean = false // 是否是语法符号（淡化用）
}
```

**关键设计**：`isMarker` 标记语法符号节点（如 `#`、`**`、`>`），着色时统一用灰色淡化。

### 3.2 块级解析器设计

#### 3.2.1 解析策略

块级解析采用**行导向的状态机**，逐行读取，根据行首特征决定块的开始/继续/结束。

```
解析流程：
1. 逐行读取输入文本
2. 对每行进行"开头特征检测"：
   - ^#{1,6}\s → 标题
   - ^>\s? → 引用
   - ^[-*+]\s → 无序列表项
   - ^\d+[.)]\s → 有序列表项
   - ^```{1,} → 代码块围栏开始/结束
   - ^~~~{1,} → 代码块围栏（波浪线）
   - ^\| → 表格行
   - ^[-*_]{3,}\s*$ → 水平分隔线
   - ^<!-- → HTML 注释
   - ^<[a-zA-Z] → HTML 块
   - 空行 → 块分隔
   - 其他 → 段落
3. 根据当前状态和行特征，执行状态转换
4. 代码块特殊处理：进入代码块后，直到遇到匹配的围栏才结束
5. 表格特殊处理：需要检测分隔行（|---|---|）来确认是表格
```

#### 3.2.2 块级解析优先级

当一行可能匹配多种块类型时，按以下优先级判断（参考 CommonMark 规范）：

1. 代码块围栏（```）
2. 水平分隔线（---）
3. 标题（#）
4. 引用（>）
5. 列表（- / 1.）
6. HTML 块
7. 表格（需要上下文判断）
8. 段落（默认）

#### 3.2.3 嵌套处理

块级元素可以嵌套，维护一个"块栈"：

```
示例：引用里的列表
> - 项目1
> - 项目2

解析过程：
1. 遇到 > → 开始 BlockQuote，压入栈
2. 遇到 > - → 在 BlockQuote 内开始 BulletList，压入栈
3. 遇到 > - → 继续 ListItem
4. 空行 → 弹出 List，弹出 BlockQuote
```

### 3.3 行内解析器设计

#### 3.3.1 解析策略

行内解析采用**递归下降解析器**，从左到右扫描，遇到特殊字符时递归解析。

```
解析流程：
1. 从左到右扫描文本
2. 遇到特殊字符时，尝试匹配对应的行内语法：
   - ** 或 __ → 粗体（递归解析内部内容）
   - * 或 _ → 斜体（需要判断单词边界）
   - ~~ → 删除线
   - ` → 行内代码（不递归，到匹配的反引号结束）
   - [ → 链接
   - ![ → 图片
   - < → 自动链接或行内 HTML
   - $ → 数学公式（可选扩展）
3. 普通字符累积为 Text 节点
4. 解析完成后，合并相邻的 Text 节点
```

#### 3.3.2 行内解析优先级

| 优先级 | 语法 | 说明 |
|--------|------|------|
| 1 | 行内代码（`` ` ``） | 最高优先级，内部不解析任何语法 |
| 2 | HTML 标签（`<...>`） | 行内 HTML 内部不解析 |
| 3 | 图片（`![...](...)`） | 图片的 alt 文本不解析行内语法 |
| 4 | 链接（`[...](...)`） | 链接文本可解析行内语法（除链接和图片） |
| 5 | 粗体（`**`/`__`） | 可嵌套斜体、行内代码等 |
| 6 | 斜体（`*`/`_`） | 可嵌套粗体等 |
| 7 | 删除线（`~~`） | 可嵌套其他语法 |
| 8 | 数学公式（`$`） | 内部不解析 |
| 9 | 自动链接（`<url>`） | - |
| 10 | 纯文本 | 默认 |

#### 3.3.3 关键难点处理

**斜体的单词边界判断**：
- `*hello*` → 斜体（`*` 在单词边界）
- `hello*world*` → 不是斜体（`*` 在单词中间）
- `hello *world*` → 斜体（`*` 前有空格）
- 解决方案：`*` 开头要求前一个字符是非单词字符或行首；`_` 更严格，要求前后都是单词边界

**链接的多种形式**：
- 行内链接：`[text](url "title")`
- 引用链接：`[text][ref]`，需要在文档中查找 `[ref]: url`
- 快捷引用：`[ref]`，ref 同时作为文本和引用键
- 自动链接：`<https://example.com>`

**嵌套深度限制**：
- 限制最大嵌套深度（默认 10 层），超过后当纯文本处理，避免性能问题和解析歧义

### 3.4 增量解析设计

#### 3.4.1 行级增量

块级解析是行导向的，天然适合增量：

```
1. 每行计算快速哈希（FNV-1a，速度优先）
2. 用户修改文本时，对比修改前后的行哈希
3. 找到第一个变化的行（startDirtyLine）和最后一个变化的行（endDirtyLine）
4. 只重新解析 [startDirtyLine - context, endDirtyLine + context] 范围
   （context 是上下文行数，默认 10 行，用于处理块边界）
5. 未变化的块直接复用旧 AST 节点
```

#### 3.4.2 脏标记传播

```
1. 行级解析后，标记受影响的块级节点为"脏"
2. 脏块的行内解析需要重新执行
3. 脏块的着色需要重新执行
4. 脏块的 Span 缓存需要失效
5. 非脏块的所有缓存保持不变
```

#### 3.4.3 行内增量

```
策略：
1. 如果修改只在一个段落内，只重新解析该段落的行内
2. 如果修改涉及块边界（如插入空行），重新解析受影响的块
3. 行内解析的结果（行内 AST）按段落缓存
4. 段落内容未变化时，直接复用行内 AST
```

## 4. 着色策略设计（复用代码主题）

### 4.1 核心策略：符号淡化 + 内容高亮

```
着色规则：
1. 语法符号节点（isMarker=true）→ 统一用灰色（代码主题的 comment 颜色或专门的淡化色）
2. 内容节点 → 根据 Scope 映射到代码主题的 Token 颜色
3. 行内代码内容 → 委托代码高亮引擎，生成带颜色的 Span
4. 代码块内容 → 委托代码高亮引擎，生成带颜色的 Span
```

**示例效果**：

```
# 标题文字
│  │
│  └── 内容：蓝色（keyword 色）
└────── 符号：灰色（淡化）

**粗体文字**
│  │      │
│  │      └── 内容：黄色（function 色）
│  └───────── 符号：灰色（淡化）
└──────────── 符号：灰色（淡化）

> 引用文字
│  │
│  └── 内容：绿色（comment 色，斜体）
└────── 符号：灰色（淡化）

`print("hello")`
│  │               │
│  │               └── 符号：灰色（淡化）
│  └────────────────── 内容：代码高亮（print=蓝色, "hello"=橙色）
└───────────────────── 符号：灰色（淡化）
```

### 4.3 语法符号淡化色

**淡化色来源**（按优先级）：
1. 代码主题的 `comment` 颜色（通常是灰色/绿色，对比度低）
2. 如果 comment 颜色太鲜艳（如亮绿色），则用专门的淡化色：前景色的 50% 透明度

```kotlin
// 淡化色计算
fun getMarkerColor(theme: CodeTheme): Color {
    val commentColor = theme.getTokenColor("comment")
    // 如果 comment 颜色的饱和度 > 50%，则用前景色的 50% 透明度
    return if (commentColor.saturation > 0.5f) {
        theme.foregroundColor.copy(alpha = 0.5f)
    } else {
        commentColor
    }
}
```

### 4.4 行内代码高亮

行内代码是重点，必须做语法高亮，与代码块同质量。

#### 4.4.1 高亮流程

```
行内代码 `print("hello")` 高亮流程：
1. 解析器识别行内代码，提取内容 "print(\"hello\")"
2. InlineCodeHighlighter 处理：
   a. 语言自动检测（根据代码内容特征）
   b. 委托 CodeHighlighter 高亮，传入检测到的语言
   c. CodeHighlighter 返回 Token 列表（带颜色）
   d. 转换为 MarkdownSpan 列表
3. 反引号标记用灰色淡化
4. 代码内容用 CodeHighlighter 返回的颜色
```

#### 4.4.2 语言自动检测

```
检测策略（按优先级）：
1. 上下文推断：如果行内代码在 Python 代码块附近，优先用 Python
2. 特征匹配：
   - 包含 `def ` / `import ` / `print(` → Python
   - 包含 `function ` / `const ` / `=>` → JavaScript
   - 包含 `fn ` / `let mut ` / `::` → Rust
   - 包含 `func ` / `import "` → Go
   - 包含 `public class ` / `System.out` → Java
   - 包含 `<?php` / `$variable` → PHP
   - 包含 `<html>` / `<div>` → HTML
   - 包含 `SELECT ` / `FROM ` / `WHERE ` → SQL
3. 启发式：根据语法符号（括号类型、注释符号等）
4. 兜底：纯文本（只有等宽字体，无颜色）
```

#### 4.4.3 性能优化

```
1. 缓存：相同内容的行内代码只高亮一次（LRU 缓存，默认 500 条）
2. 长度限制：超过 500 字符的行内代码不做语法高亮（性能考虑），只用等宽字体+背景色
3. 异步高亮：行内代码高亮异步执行，不阻塞主线程
4. 批量处理：可视区域内的行内代码批量高亮
```

### 4.5 代码块高亮

代码块高亮直接委托现有代码高亮引擎，与纯代码文件完全一致。

```
代码块高亮流程：
1. 解析器识别代码块围栏和语言标识（```python）
2. 围栏和语言标识用灰色淡化
3. 代码内容委托 CodeHighlighter：
   - 传入：代码文本 + 语言类型
   - 返回：带颜色的 Token 列表
4. 代码块内容的 Span 由 CodeHighlighter 的 Token 转换而来
5. 嵌套语言（HTML 内的 CSS/JS）由 CodeHighlighter 自己处理
```

## 5. 性能优化专项设计

### 5.1 性能目标（硬指标）

| 指标 | 目标值 | 测试条件 |
|------|--------|---------|
| 首屏渲染时间 | < 300ms | 1MB 文件，冷启动 |
| 首屏渲染时间 | < 500ms | 10MB 文件，冷启动 |
| 滚动帧率 | ≥ 55fps | 10MB 文件，快速滚动 |
| 输入延迟 | < 16ms | 单次按键到高亮更新（任意大小文件） |
| 增量解析时间 | < 3ms | 修改单行后的重新解析 |
| 主题切换 | < 50ms | 切换代码主题后重新着色（不重新解析） |
| 内存占用 | < 30MB | 1MB 文件稳定状态 |
| 内存占用 | < 80MB | 10MB 文件稳定状态 |
| 全量解析时间 | < 1s | 1MB 文件全量解析 |
| 全量解析时间 | < 5s | 10MB 文件全量解析 |

### 5.2 增量解析优化

#### 5.2.1 行哈希与脏行检测

```
1. 每行计算快速哈希（FNV-1a，不是 SHA，速度优先）
2. 行哈希数组缓存，修改时对比：
   - 找到第一个哈希变化的行（startDirty）
   - 找到最后一个哈希变化的行（endDirty）
3. 扩展脏范围：向上向下各扩展 N 行（默认 10 行），处理块边界
4. 只重新解析扩展后的脏范围
5. 范围外的块直接复用旧 AST
```

#### 5.2.2 块级缓存

```
每个块级节点缓存：
- 块的起始行和结束行
- 块的哈希（基于内容行哈希）
- 块的行内 AST（如果已解析）
- 块的 Span 列表（如果已着色）

复用条件：
- 块的行范围未变化
- 块的内容哈希未变化
- 块的父节点未变化（嵌套上下文未变）

复用时直接使用缓存的行内 AST 和 Span，跳过解析和着色
```

#### 5.2.3 行内解析缓存

```
按段落缓存行内解析结果：
- 缓存键：段落内容哈希 + 段落所在块的类型
- 缓存值：行内 AST
- 缓存大小：LRU，默认 2000 个段落

命中条件：
- 段落内容完全相同
- 段落的上下文（是否在引用/列表中）相同

未命中时重新解析，结果写入缓存
```

### 5.3 虚拟滚动优化

#### 5.3.1 只渲染可视区域

```
1. 维护可视区域的行范围 [visibleStartLine, visibleEndLine]
2. 滚动时更新可视范围
3. 只请求可视范围内的 Span 进行渲染
4. 可视范围外的行不渲染（占位，高度预计算）
5. 预渲染缓冲区：可视区域上下各预渲染 N 行（默认 30 行），减少滚动时的空白
```

#### 5.3.2 行高预计算

```
因为标题与正文同字号（v1.1 决策），行高计算大大简化：

行高规则：
1. 普通文本行：固定行高（由字号和行间距决定）
2. 代码块行：固定行高（等宽字体，通常比正文小 1-2sp）
3. 表格行：固定行高（表格内容不自动换行，横向滚动）
4. 分隔线行：固定行高（较矮）

因为所有行高都是固定的（不依赖内容），行高可以直接计算，不需要测量：
- 行高 = 基础行高（根据行类型查表）
- 总高度 = 行数 × 平均行高（快速估算）
- 精确高度 = 逐行累加（精确计算，缓存结果）
```

#### 5.3.3 滚动性能优化

```
1. 滚动事件节流：使用 requestAnimationFrame 同步，避免高频回调
2. 增量渲染：滚动时只渲染新进入可视区域的行，不重绘已渲染的行
3. 离屏回收：滚出可视区域的行立即回收渲染资源
4. 大文件优化：超过 10000 行时，降低预渲染缓冲区大小（30→10行）
5. GPU 加速：使用硬件加速的图层渲染，减少 CPU 绘制压力
6. 滚动预测：根据滚动速度预测即将进入可视区域的行，提前渲染
```

### 5.4 着色缓存优化

#### 5.4.1 多级缓存

```
L1：Scope → 颜色 缓存（主题级，切换主题时失效）
   - 键：Scope 字符串
   - 值：Color 对象
   - 大小：无限制（Scope 数量有限，通常 < 50）

L2：块 → Span 列表缓存（块级，块内容变化时失效）
   - 键：块 ID + 主题版本
   - 值：Span 列表
   - 大小：LRU，默认 1000 个块

L3：行 → Span 列表缓存（行级，行内容变化时失效）
   - 键：行哈希 + 行所在块类型 + 主题版本
   - 值：Span 列表
   - 大小：LRU，默认 5000 行
```

#### 5.4.2 着色懒计算

```
1. 解析完成后不立即着色（只生成 AST）
2. 着色在渲染时按需执行：只着色可视区域内的块
3. 着色结果写入 L2/L3 缓存，后续滚动直接复用
4. 非可视区域的块保持"未着色"状态，不占用计算资源
5. 主题切换时：只清除 L1/L2/L3 缓存，不重新解析 AST，然后按需重新着色
```

### 5.5 行内代码高亮性能优化

```
1. 长度阈值：≤ 500 字符的行内代码做语法高亮，> 500 字符只用等宽字体
2. LRU 缓存：相同内容只高亮一次，默认 500 条
3. 异步执行：行内代码高亮在后台线程执行，不阻塞主线程
4. 批量处理：可视区域内的行内代码批量提交高亮
5. 优先级：可视区域内的行内代码优先高亮，离屏的延迟处理
6. 降级策略：高负载时临时关闭行内代码高亮（只用背景色），负载恢复后自动开启
```

### 5.6 大文件特殊处理

#### 5.6.1 分级策略

| 文件大小 | 策略 |
|---------|------|
| < 1MB | 全量解析 + 全量着色 + 完整虚拟滚动 + 行内代码高亮 |
| 1-5MB | 全量解析 + 按需着色 + 虚拟滚动 + 行内代码高亮（≤300字符） |
| 5-10MB | 增量解析（只解析可视区域附近）+ 按需着色 + 极简虚拟滚动 + 行内代码只用背景色 |
| > 10MB | 提示用户文件过大，建议使用纯文本模式（无高亮）或分段加载 |

#### 5.6.2 分段加载（超大文件）

```
超大文件（>10MB）采用分段加载：
1. 初始只加载前 2000 行
2. 滚动接近底部时，异步加载下一段（2000 行）
3. 已加载的段落保持在内存中，不卸载
4. 显示加载进度提示
5. 提供"跳转到行号"功能，快速定位
6. 纯文本模式（无高亮）作为兜底，保证任何大小文件都能打开
```

#### 5.6.3 高负载降级

```
监控指标：
- 主线程帧率（< 30fps 持续 1 秒 → 高负载）
- 输入延迟（> 50ms 持续 3 次 → 高负载）
- 内存占用（> 80% 可用内存 → 高负载）

降级策略（逐级）：
1. 关闭行内代码高亮（只用背景色）
2. 减少预渲染缓冲区（30→10行）
3. 降低着色质量（粗体/斜体只用颜色，不设置 fontStyle）
4. 关闭增量解析的上下文扩展（10→3行）
5. 切换到纯文本模式（无高亮）

恢复策略：
- 负载恢复正常后 5 秒，逐级恢复功能
- 恢复顺序与降级相反
```

1. 保持 AST、着色、Span 缓存不变
2. 启用交互层（光标、输入法、撤销栈）
3. 光标定位到上次编辑位置（或文档开头）
4. 显示行号（如果开启）

编辑 → 查看：
1. 保存当前光标位置（用于下次切换回来）
2. 禁用交互层（隐藏光标、禁用输入法）
3. 保持 AST、着色、Span 缓存不变
4. 隐藏行号（如果查看模式不显示）

核心原则：切换模式不触发重新解析或重新着色，只有交互层变化。
```

## 7. 代码块与行内代码高亮

### 7.1 代码块高亮

**核心设计**：Markdown 解析器只识别代码块边界和语言，代码块内部的高亮完全委托给现有代码高亮引擎。

```
Markdown 解析器遇到代码块：
    │
    ▼
1. 识别围栏（``` 或 ~~~）
2. 识别语言标识（```python）
3. 围栏和语言标识用灰色淡化（markup.codeblock.fence / markup.codeblock.language）
4. 代码内容委托代码高亮引擎：
   - 传入：代码文本 + 语言类型
   - 返回：代码高亮的 Token 列表
   - Token 列表包装成 CodeBlockContent 节点
5. 代码块内容的 Span 由代码高亮引擎的 Token 转换而来
```

**保证**：
- 代码块高亮质量与纯代码文件完全一致
- 嵌套语言（HTML 内的 CSS/JS）由代码高亮引擎自己处理
- 后续升级代码高亮引擎，Markdown 自动受益

### 7.2 行内代码高亮（重点）

行内代码是 v1.1 确认的重点，必须做语法高亮。

#### 7.2.1 高亮流程

```
行内代码 `print("hello")` 高亮流程：
1. 解析器识别行内代码，提取内容 "print(\"hello\")"
2. InlineCodeHighlighter 处理：
   a. 检查缓存：相同内容是否已高亮过
   b. 未命中缓存 → 语言自动检测
   c. 委托 CodeHighlighter 高亮（异步，后台线程）
   d. CodeHighlighter 返回 Token 列表
   e. 转换为 MarkdownSpan 列表
   f. 写入缓存
3. 反引号标记用灰色淡化
4. 代码内容用 CodeHighlighter 返回的颜色
```

#### 7.2.2 语言自动检测

```
检测策略（按优先级）：
1. 上下文推断：
   - 行内代码所在段落附近有代码块，使用该代码块的语言
   - 文档标题或首段提到语言名称，优先使用
2. 特征匹配（按语言特征）：
   - Python：`def `、`import `、`print(`、`elif `、`self.`
   - JavaScript：`function `、`const `、`let `、`=>`、`console.log`
   - TypeScript：`: string`、`: number`、`interface `、`type `
   - Rust：`fn `、`let mut `、`::`、`impl `、`crate::`
   - Go：`func `、`import "`、`package `、`&`、`go func`
   - Java：`public class `、`System.out`、`@Override`、`new `
   - PHP：`<?php`、`$variable`、`->`、`echo `
   - HTML：`<html>`、`<div>`、`<span>`、`class=`
   - CSS：`{ }`、`color:`、`font-size:`、`@media`
   - SQL：`SELECT `、`FROM `、`WHERE `、`INSERT INTO`、`JOIN `
   - Shell：`#!/bin/bash`、`echo `、`export `、`|`、`grep `
   - C/C++：`#include`、`int main`、`printf(`、`std::`
3. 启发式：
   - 包含 `$` 变量符号 → PHP/Shell/Perl
   - 注释符号（# → Python/Shell/Ruby，// → C/Java/JS，-- → SQL/Lua）
   - 括号类型（{ } → C 系，end → Ruby/Pascal）
4. 兜底：纯文本（只有等宽字体，无颜色）
```

#### 7.2.3 性能控制

```
1. 长度阈值：≤ 500 字符做语法高亮，> 500 字符只用等宽字体+背景色
2. LRU 缓存：默认 500 条，相同内容只高亮一次
3. 异步执行：后台线程高亮，不阻塞主线程
4. 批量处理：可视区域内的行内代码批量提交
5. 优先级：可视区域内 > 预渲染区域 > 离屏
6. 降级：高负载时临时关闭行内代码高亮（只用背景色）
```

#### 7.2.4 行内代码的视觉样式

```
行内代码视觉效果：
1. 反引号：灰色淡化（markup.inline.code.marker）
2. 代码内容：代码高亮颜色（委托 CodeHighlighter）
3. 背景色：代码主题的代码块背景色（浅色，与正文区分）
4. 圆角：4dp 圆角
5. 内边距：左右 4dp，上下 2dp
6. 字体：等宽字体（与代码块一致）
7. 字号：比正文小 1-2sp（可选，v1.1 先同字号）
```

## 8. 扩展语法支持

### 8.1 GFM 扩展（内建，默认启用）

| 语法 | 高亮效果 |
|------|---------|
| 表格 | `\|` 符号灰色淡化，表格内容用 type 颜色（浅绿色），分隔行 `|---\|` 灰色淡化 |
| 任务列表 | `- [ ]` 未完成用 list 颜色，`- [x]` 已完成用 string 颜色+删除线 |
| 删除线 | `~~` 符号灰色淡化，内容用 comment 颜色+删除线 |
| 自动链接 | 裸 URL 自动识别为链接，用 link.url 颜色+下划线 |

### 8.2 可选扩展（只高亮不渲染）

| 扩展 | 语法 | 高亮效果 | 默认状态 |
|------|------|---------|---------|
| 数学公式 | `$...$` / `$$...$$` | `$` 符号灰色淡化，公式内容用 variable 颜色（粉紫色） | 禁用 |
| Mermaid | ```` ```mermaid ```` | 作为代码块的一种，语言为 mermaid，内容用代码高亮 | 禁用 |
| 脚注 | `[^1]` + `[^1]:` | `[^1]` 引用用 variable 颜色，`[^1]:` 定义用 comment 颜色 | 禁用 |
| 定义列表 | `术语\n: 定义` | 术语用 keyword 颜色，`:` 符号灰色淡化，定义用正文颜色 | 禁用 |

**设计原则**：
- 核心语法（CommonMark）内建，不可禁用
- GFM 扩展内建，默认启用，可在设置中关闭
- 高级扩展（数学公式/Mermaid/脚注）轻量支持，只做语法高亮，不做渲染
- 启用扩展不需要重新解析整个文档（增量解析受影响的部分）

### 9.3 门面接口

```kotlin
interface MarkdownHighlighter {
    /** 设置全文本（全量解析） */
    fun setText(text: String)

    /** 增量更新文本（只解析受影响的部分） */
    fun updateText(range: IntRange, newText: String)

    /** 获取指定行范围的 Span 列表（虚拟滚动用） */
    fun getSpansForLines(startLine: Int, endLine: Int): List<MarkdownSpan>

    /** 获取指定行的高度 */
    fun getLineHeight(line: Int): Float

    /** 获取总行数 */
    fun getLineCount(): Int

    /** 获取文档总高度 */
    fun getDocumentHeight(): Float

    /** 根据行号和列号获取偏移量（光标用） */
    fun getOffset(line: Int, col: Int): Int

    /** 根据偏移量获取行号和列号（光标用） */
    fun getLineCol(offset: Int): Pair<Int, Int>

    /** 获取 AST（调试用） */
    fun getAst(): MarkdownAst

    /** 清除缓存（主题切换时调用） */
    fun clearCache()
}
```

### 9.4 渐进式替换策略

```
阶段一：MarkdownHighlighter 作为新的高亮后端
- 现有查看器/编辑器保持不变
- MarkdownHighlighter 作为新的高亮选项
- 用户可在设置中选择"使用新 Markdown 高亮"
- A/B 对比验证稳定性

阶段二：Markdown 文件默认使用新引擎
- .md 文件默认使用 MarkdownHighlighter
- 旧引擎作为备选（设置中可回退）
- 收集用户反馈，修复问题

阶段三：完全替换
- 移除旧的 Markdown 高亮代码
- MarkdownHighlighter 成为唯一的 Markdown 高亮方案
- 代码清理和性能优化
```

### 9.5 与代码高亮主题的统一

```
主题切换流程：
1. 用户在设置中切换代码高亮主题（如 Dark → Light）
2. CodeThemeManager 通知所有监听者
3. MarkdownHighlighter 收到通知，清除着色缓存（L1/L2/L3）
4. 可视区域内的块按需重新着色（使用新主题的颜色映射）
5. 查看器/编辑器刷新显示

保证：
- 代码和 Markdown 主题始终同步
- 用户不需要单独设置 Markdown 主题
- 切换主题不重新解析 AST，只重新着色（< 50ms）
```

### 12.3 性能优化检查清单

- [ ] 增量解析：修改单行不触发全量解析
- [ ] 块级缓存：未变化的块不重新解析
- [ ] 行内缓存：相同段落不重复解析行内
- [ ] 着色缓存：Scope→颜色缓存，块→Span 缓存

### 12.4 常见 Markdown 边缘情况

| 边缘情况 | 说明 | 处理方式 |
|---------|------|---------|
| 未闭合的粗体 | `**text` 没有闭合 | 当纯文本处理，不高亮 |
| 代码块内的 Markdown | `````` ``` ```` 内的 `#` 不解析为标题 | 代码块内不解析任何 Markdown 语法 |
| 列表内的代码块 | 列表项缩进 4 空格的代码块 | 识别缩进代码块 |
| 引用内的列表 | `> - item` | 嵌套解析 |
| 空标题 | `#` 后面没有文本 | 仍然高亮为标题 |
| 链接内的粗体 | `[**text**](url)` | 链接文本内解析粗体 |
| 图片内的链接 | `[![alt](image_url)](url)` | 图片作为链接文本 |
| 转义字符 | `\*` 不解析为斜体 | 反斜杠转义 |
| 自动链接 | `<https://example.com>` | 识别为自动链接 |
| 裸 URL | `https://example.com`（GFM） | GFM 自动链接 |
| 表格分隔行 | `|---|---|` | 必须在第二行才识别为表格 |
| 任务列表 | `- [ ]` / `- [x]` | GFM 扩展 |
| 删除线 | `~~text~~` | GFM 扩展 |
| 多个连续空行 | 多个空行只算一个块分隔 | 合并空行 |
| 行尾两个空格 | 硬换行 | 识别为 HardLineBreak |
| 缩进代码块 | 4 空格缩进的代码块（无围栏） | 识别为 CodeBlock（isFenced=false） |
