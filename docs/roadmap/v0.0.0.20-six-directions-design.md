## 一、启动动画打磨

### 1.1 现状分析

当前启动动画为第一版实现（v0.0.0.19上线），采用五阶段6秒动画：粒子散开(1.5s) → 聚合拼组(2s) → 停留展示(1s) → 玻璃破碎(1s) → 渐入应用(0.5s)。核心文件位于 `core/splash/`，包含粒子系统、Voronoi玻璃破碎、3D透视变换。

**已知问题与优化空间**：
- 粒子数量固定800-1200，低端机可能卡顿
- 破碎效果的3D透视参数未精细调优
- 主题色适配仅用了background和primary，未充分利用主题色板
- 跳过按钮样式较简单，缺少视觉层次
- 动画结束后与主界面的过渡可能有闪烁
- 没有动画完成后的初始化状态同步机制
- 用户无法选择动画风格或关闭动画
- 初始化进度不可见，用户不知道应用在做什么

### 1.2 优化目标

1. 动画流畅度：中高端机60fps，低端机30fps以上不丢帧
2. 视觉精致度：粒子运动自然、破碎有真实感、文字清晰可辨
3. 主题适配：深色/浅色主题下均有良好视觉效果
4. 性能自适应：根据设备性能自动调整粒子数量和特效等级
5. 过渡平滑：动画结束到主界面无闪烁、无白屏
6. 用户可控：动画风格可选、可关闭、初始化进度可见

### 1.3 功能点详细设计

#### F1.1 性能自适应降级系统

**设计**：在动画开始前检测设备性能，动态调整特效等级。

- **性能检测指标**：
  - CPU核心数（<4核为低端）
  - 内存总量（<4GB为低端）
  - 屏幕分辨率（>1080p为高负载）
  - Android版本（<8.0为低端）
  - 设备性能等级（通过 `ActivityManager.getMemoryClass()` 判断）

- **三级特效等级**：
  | 等级 | 粒子数 | 破碎碎片 | 3D效果 | 拖尾 | 动画时长 | 适用 |
  |------|--------|----------|--------|------|----------|------|
  | 高 | 1200 | 40块 | 完整透视+旋转 | 有 | 6s | 高端机（≥8核≥6GB） |
  | 中 | 800 | 25块 | 简化透视 | 简化 | 5s | 中端机（4-7核4-6GB） |
  | 低 | 400 | 12块 | 无3D，仅2D缩放 | 无 | 4s | 低端机（<4核<4GB） |

- **实现**：`ParticleSystem` 构造时接收 `qualityLevel` 参数，根据等级初始化不同数量的粒子和破碎参数。性能检测结果缓存到 `AppInitState`，避免重复检测。

#### F1.2 粒子运动参数精细调优

**散开阶段（0-1.5s）**：
- 速度分层：30%粒子高速(15-25dp/帧)作为"先锋"，50%中速(8-15dp/帧)，20%低速(3-8dp/帧)作为"尾迹"
- 角度分布：中心区域粒子角度偏差±15°，边缘粒子±45°，模拟爆炸的中心密集效果
- 粒子大小：3-8dp随机分布，大粒子(>6dp)占20%，中粒子(4-6dp)占50%，小粒子(<4dp)占30%
- 透明度：散开时alpha 0.8→1.0，边缘粒子稍低(0.6)

**聚合阶段（1.5-3.5s）**：
- 粒子按距离目标位置的远近分批次到达——近的先到(1.5-2.5s)，远的后到(2.0-3.5s)
- 运动曲线：easeOutCubic（前快后慢），最后200ms有轻微回弹(3%幅度)
- 聚合时粒子大小统一收敛到文字笔画宽度(2-3dp)

**停留阶段（3.5-4.5s）**：
- 文字轻微呼吸效果：scale 1.0→1.02→1.0，周期1s
- 粒子在文字边缘有微小抖动(±1dp)，模拟能量感
- 背景渐变缓慢流动(5%幅度)

**破碎阶段（4.5-5.5s）**：
- 粒子飞散速度：中心粒子快(20-30dp/帧)、边缘粒子慢(8-15dp/帧)
- 重力加速度：随时间递增（0→0.5dp/帧²），模拟真实下落
- 旋转：每个碎片随机旋转角速度(5-15°/帧)
- 透明度：破碎后0.5s内alpha 1→0

#### F1.3 玻璃破碎3D效果增强

**碎片分层**：
- 前景层(30%)：旋转角度大(45-90°)，位移远(100-200dp)，先飞出，Z轴靠前
- 中景层(40%)：旋转角度中(20-45°)，位移中(50-100dp)，Z轴居中
- 背景层(30%)：旋转角度小(0-20°)，位移近(20-50dp)，后飞出，Z轴靠后

**视觉细节**：
- 碎片边缘添加1px白色半透明(alpha 0.6)描边，模拟玻璃断面反光
- 破碎瞬间(4.5s)全屏闪白1帧，然后100ms内alpha 1→0
- 碎片之间有2-3px间隙，增强碎裂感
- 碎片形状：Voronoi多边形，边数3-7，避免过于规则

**3D透视参数**：
- 相机距离：屏幕高度的1.5倍
- 透视强度：0.8（0=无透视，1=强透视）
- 旋转轴：随机X/Y/Z组合，每个碎片不同
- 消失点：屏幕中心偏上10%

#### F1.4 主题色深度适配

**背景渐变**：
- 深色主题：`background` → `primary`(12%透明度) 径向渐变，中心偏上，渐变半径屏幕宽度的80%
- 浅色主题：`background` → `primary`(8%透明度) 径向渐变，中心偏上
- 动画过程中渐变中心缓慢移动(±5%屏幕宽度)，增加流动感

**粒子颜色**：
- 光点粒子：70%用 `onBackground`，30%用 `primary`（主题色点缀）
- 碎片粒子：90%用 `onBackground`，10%用 `primary`
- 聚合完成时：文字颜色从粒子混合色渐变为纯 `onBackground`，过渡200ms

**破碎闪光**：
- 深色主题：闪白色(alpha 0.8)
- 浅色主题：闪 `primary` 色(alpha 0.5)

**文字样式**：
- 字体：`Typography.displaySmall`（标题级）
- 字重：Medium(500)
- 字号：根据屏幕宽度自适应（32-48sp）
- 字间距：0.5sp

#### F1.5 跳过按钮视觉升级

**布局**：
- 位置：右上角，距状态栏16dp，距右边缘16dp
- 尺寸：高度32dp，宽度自适应（内容+24dp水平内边距）
- 形状：圆角16dp（药丸形）

**样式**：
- 背景：`Surface`(alpha 0.5) + 1px `outlineVariant` 描边
- 文字：「跳过」用 `onSurfaceVariant`(12sp)，倒计时数字用 `primary`(14sp粗体)
- 文字间距：「跳过」和数字之间8dp

**交互状态**：
- 默认：alpha 0.7
- 悬停/按下：alpha 1.0，scale 0.95（100ms动画）
- 倒计时最后2秒：数字颜色变为 `error`，按钮背景alpha提升到0.8
- 点击后：按钮消失(200ms淡出)，动画立即进入破碎阶段

#### F1.6 动画结束过渡优化

**交叉淡入淡出**：
- 5.0s时：主界面开始预加载（alpha 0→0.3，完成首帧测量和布局）
- 5.5-6.0s：覆盖层alpha 1→0，主界面alpha 0.3→1，交叉过渡
- 6.0s：覆盖层完全移除，主界面完全可见

**预加载机制**：
- 主界面在动画期间后台完成：数据加载、首帧测量、布局计算
- 使用 `setKeepOnScreenCondition` 确保动画期间不显示空白
- 预加载超时保护：如果3s内未完成，强制显示主界面（避免无限等待）

#### F1.7 初始化进度指示（新增）

**设计**：动画期间在底部显示应用初始化进度，让用户知道应用在做什么。

- **进度显示**：
  - 位置：屏幕底部，距底部48dp，水平居中
  - 样式：细线进度条(高度2dp，宽度屏幕宽度的40%) + 百分比文字(12sp, onSurfaceVariant)
  - 进度来源：`AppInitState` 的初始化进度（0-100%）
- **初始化阶段提示**：
  - 进度条上方显示当前阶段文字，如「正在加载模型配置」「正在初始化终端环境」
  - 阶段文字12sp，onSurfaceVariant，居中
  - 阶段切换时有淡入淡出动画(200ms)
- **初始化阶段定义**：
  | 阶段 | 进度范围 | 提示文字 |
  |------|----------|----------|
  | 数据层 | 0-20% | 正在加载本地数据 |
  | AI服务 | 20-45% | 正在初始化AI服务 |
  | 终端环境 | 45-70% | 正在准备终端环境 |
  | 浏览器引擎 | 70-85% | 正在初始化浏览器 |
  | 界面渲染 | 85-100% | 正在准备界面 |

#### F1.8 动画风格选择（新增）

**设计**：设置中增加启动动画风格选项，用户可选择。

- **可选风格**：
  | 风格 | 描述 | 适用 |
  |------|------|------|
  | 粒子聚合（默认） | 当前的粒子散开→聚合→破碎效果 | 大部分用户 |
  | 简约渐变 | Logo渐入+背景渐变流动，无粒子 | 低端机/偏好简约 |
  | 经典Logo | Logo从中心放大+旋转，快速进入 | 追求启动速度 |
  | 关闭 | 直接显示主界面，无动画 | 最快启动 |
- **设置位置**：设置 → 外观 → 启动动画风格
- **持久化**：选择结果保存到 `ThemeSettingsRepository`
- **预览**：设置项旁有「预览」按钮，点击播放5秒动画预览

### 1.5 技术实现

**文件结构**：
```
core/splash/
├── ParticleSplashScreen.kt      # 主入口（修改：进度指示、风格选择）
├── ParticleSystem.kt            # 粒子系统（修改：性能等级、运动参数）
├── GlassShatterEffect.kt        # 破碎效果（修改：碎片分层、高光、3D参数）
├── ParticleSplashCanvas.kt      # 画布渲染（修改：主题色、闪光）
├── SplashAnimationState.kt      # 动画状态机（修改：阶段定义）
├── SplashPerformanceDetector.kt # 新增：设备性能检测
├── SplashStyle.kt               # 新增：动画风格枚举
└── MinimalSplashScreen.kt       # 新增：简约渐变风格
```

**性能优化**：
- 粒子位置计算在 `withFrameNanos` 中批量处理，避免逐粒子重组
- 破碎碎片使用预计算的Path，动画时只变换矩阵
- 离屏文字渲染只做一次，缓存为Bitmap
- 低端机关闭3D透视和裂纹效果，直接粒子飞散
- 使用 `Canvas` 直接绘制，不使用Composable重组

### 1.6 测试策略

- **单元测试**：性能检测逻辑（不同设备参数→正确等级）、动画状态机转换

- **性能测试**：低端机(4核4GB)帧率≥30fps，中端机≥45fps，高端机≥55fps
- **视觉测试**：深色/浅色主题下截图对比，确保颜色正确
- **兼容性测试**：Android 8-14各版本，不同屏幕尺寸(小屏/平板/折叠屏)

## 二、AI 对话体验

### 2.1 现状分析

当前对话界面位于 `feature/agent/presentation/component/`，核心文件 `AIChatPanel.kt`（730+行）。包含消息列表、输入栏、模型选择、附件、技能面板等。

**已知问题与优化空间**：
- 流式输出的Markdown渲染较基础，代码块缺少语法高亮
- 长对话中定位历史消息困难，无搜索功能
- 模型切换时上下文处理策略不明确
- 消息列表的滚动行为在流式输出时可能跳动
- 缺少消息复制、重新生成、编辑等快捷操作
- 多轮对话的token消耗无可视化
- 无对话模板/预设提示词功能
- 无法导出对话记录
- 无法同时对比多个模型的回答

### 2.2 优化目标

1. 内容渲染：Markdown完整支持，代码块语法高亮，表格/列表美观
2. 消息管理：搜索定位、快捷操作、历史回溯、导出分享
3. 交互流畅：流式输出不跳动、滚动自然、输入体验优化
4. 上下文感知：模型切换策略清晰、token消耗可见
5. 效率提升：对话模板、多模型对比、快捷命令

### 2.3 功能点详细设计

#### F2.1 Markdown渲染增强

**代码块语法高亮**：
- 支持语言：Kotlin、Python、JavaScript、TypeScript、Java、Bash、SQL、JSON、YAML、Markdown、XML、C/C++、Go、Rust
- 高亮颜色（深色主题）：
  | 元素 | 颜色 |
  |------|------|
  | 关键字 | #FF7B72（红） |
  | 字符串 | #A5D6FF（蓝） |
  | 注释 | #8B949E（灰） |
  | 数字 | #79C0FF（浅蓝） |
  | 函数名 | #D2A8FF（紫） |
  | 类型 | #7EE787（绿） |
- 代码块样式：
  - 背景：`surfaceVariant`（深色主题下更深）
  - 圆角：12dp
  - 内边距：12dp
  - 顶部栏：语言标签(左，12sp onSurfaceVariant) + 复制按钮(右，IconButton)
  - 行号：可选，默认关闭，设置中可开启
  - 字体：等宽(JetBrains Mono或系统等宽)，13sp，行高1.5
  - 横向滚动：超宽代码可左右滑动

**表格渲染**：
- 表头背景：`primaryContainer`，文字 `onPrimaryContainer` 粗体
- 单元格内边距：8dp水平，6dp垂直
- 边框：1dp `outlineVariant`
- 隔行变色：奇数行 `surface`(30%透明度)
- 超宽表格：横向滚动，滚动条显示
- 对齐：数字右对齐，文字左对齐

**列表渲染**：
- 无序列表：圆点用 `primary` 色，直径6dp，与文字间距8dp
- 有序列表：数字用 `primary` 色粗体，等宽字体
- 嵌套缩进：每层16dp
- 任务列表：复选框(24dp)，已完成项文字加删除线+onSurfaceVariant色

**引用块**：
- 左侧4dp `primary` 色竖条
- 背景：`surfaceVariant`(50%)
- 内边距：12dp
- 文字：`onSurfaceVariant`，斜体

**链接**：
- 颜色：`primary`，下划线
- 点击：调用内置浏览器打开（非外部浏览器）
- 长链接：截断显示，悬停显示完整URL

**图片**：
- Markdown图片显示为缩略图（最大宽度100%，高度自适应）
- 点击放大查看（全屏图片查看器）
- 加载失败显示占位图标+「加载失败」

#### F2.2 对话内搜索与定位

**入口**：
- 对话页顶栏搜索图标
- 双指下滑手势唤起（可选，设置中开启）
- 快捷键：Ctrl+F（外接键盘）

**搜索面板**：
- 从顶部滑入，高度56dp
- 左侧：搜索图标(24dp)
- 中间：搜索输入框(单行，14sp)
- 右侧：清除按钮(搜索有内容时显示) + 关闭按钮
- 下方：结果计数「3/12」+ 上/下导航按钮

**搜索功能**：
- 搜索范围：当前对话所有消息（用户+AI）
- 匹配规则：全文匹配，不区分大小写，支持多关键词(空格分隔为AND)
- 结果高亮：匹配文字黄色背景(`primaryContainer`)
- 定位：点击结果或上下导航，自动滚动到对应消息
- 定位动画：平滑滚动(300ms)，消息高亮闪烁(2s，背景 `primaryContainer`→透明)

**搜索历史**：
- 保留最近10条搜索记录
- 搜索框聚焦时显示历史记录（下拉列表）
- 可清除单条或全部

**AI消息操作**：

#### F2.4 流式输出滚动优化

**智能滚动策略**：
- 用户在底部（距底部<100dp）：自动跟随新内容滚动
- 用户已上滑：暂停自动滚动，显示「↓ 新消息」悬浮按钮
- 「↓ 新消息」按钮：右下角，距输入栏16dp，圆形48dp，`primary`背景，白色箭头
- 用户点击输入框：自动滚到底部
- 新消息到达时（用户已上滑）：按钮上显示未读消息数（红色角标）

**增量渲染**：
- 流式输出时只更新最后一条消息的内容
- 使用 `LazyColumn` 的 `items` + 稳定key（消息ID）
- 消息内容使用 `remember` 缓存，避免重复解析
- 新消息追加时使用 `animateItem()` 平滑插入

**打字光标**：
- AI回复末尾显示闪烁光标「|」
- 光标样式：1dp宽，与文字同高，`primary`色
- 闪烁周期：500ms亮/500ms灭
- 输出完成后光标消失(200ms淡出)

**停止生成**：
- AI生成过程中，发送按钮变为「停止」按钮(红色方形图标)
- 点击停止：中断当前请求，保留已生成的内容

#### F2.5 模型切换上下文策略

**切换确认对话框**：

  1. **保留上下文继续**（默认，推荐）：用新模型继续当前对话，历史消息保留
  2. **清空上下文新对话**：保留历史消息但从新消息开始不携带历史（相当于新会话）
  3. **取消**
- 对话框内容：当前模型→新模型，当前对话token估算，选项说明

**上下文携带提示**：

**上下文压缩**：
- 当token超过模型窗口70%时，自动提示「是否压缩上下文？」

#### F2.6 Token消耗可视化

**位置**：对话页顶栏，模型名称旁边

**显示格式**：
- 紧凑模式：`2.3K / 128K` + 迷你进度条(高度3dp，宽度60dp)
- 展开模式（点击展开）：
  - 输入token：1,842
  - 输出token：487
  - 缓存命中：1,200（如果支持）
  - 估算费用：$0.0023（如果配置了价格）
  - 本轮消耗：输入156 + 输出89 = 245 tokens

**进度条颜色**：
- <50%：`primary`
- 50-80%：`tertiary`（警告）
- >80%：`error`（危险）

**数据来源**：
- API响应的 `usage` 字段（优先）
- 无usage时基于字符数估算：中文1字≈1.5token，英文1词≈1.3token，代码1字符≈0.3token
- 估算值标注「估算」字样

## 三、终端/容器深化

### 3.1 现状分析

终端/容器位于 `feature/terminal/`，v0.0.0.19已合并为Tab页面（容器在前）。核心功能：PRoot Alpine容器、终端模拟、SSH远程、镜像Profile管理。

**已知问题与优化空间**：
- 容器内文件只能通过终端操作，无图形化文件管理
- 终端单会话，不支持分屏或多标签
- 常用命令需要手动输入，无快捷面板
- 容器资源使用无实时监控
- 容器与宿主文件传输不方便
- 终端外观不可自定义（配色、字体）
- SSH密钥管理分散
- 无容器快照功能

### 3.2 优化目标

1. 文件管理：容器内文件图形化浏览、编辑、传输
2. 多任务：终端分屏/多会话，并行操作
3. 效率提升：常用命令快捷面板，减少重复输入
4. 资源可见：CPU/内存/存储实时监控
5. 个性化：终端主题、字体、配色可自定义
6. 安全：SSH密钥统一管理，容器快照备份

### 3.3 功能点详细设计

- 长按命令：编辑（自定义命令）/ 复制到输入框（不执行）
- 面板可折叠：点击按钮展开/收起，不占用终端空间
- 搜索过滤：面板顶部搜索框，输入关键词过滤命令
- 最近使用：面板顶部显示最近5条使用的命令

**面板样式**：
- 从底部滑出，高度为屏幕的50%
- 顶部：搜索框 + 分类Tab（横向滚动）
- 内容：网格布局(2列)，每个命令卡片(图标+名称+命令预览)
- 底部：「+ 管理自定义命令」按钮

#### F3.4 容器资源实时监控

**监控指标**：
| 指标 | 数据来源 | 显示方式 |
|------|----------|----------|
| CPU使用率 | /proc/stat 计算 | 百分比 + 迷你折线图(最近60秒) |
| 内存使用 | /proc/meminfo | 已用/总量 + 进度条 |
| 存储使用 | df命令 | 已用/总量 + 进度条 |
| 进程数 | ps命令 | 数字 + 运行中/总进程 |
| 网络流量 | /proc/net/dev（可选） | 上传/下载速率 |

**展示位置**：容器状态卡片内，2x2网格布局

**每个指标卡片**：
- 图标(24dp) + 指标名称(12sp onSurfaceVariant)
- 数值(16sp粗体)
- 迷你图表/进度条（高度20dp）
- 点击展开详情（动画展开，高度120dp）

**详情内容**：
- CPU：各核心使用率、负载均衡(1/5/15分钟)、进程TOP5
- 内存：详细分类(已用/缓存/缓冲/可用)、Swap使用
- 存储：各挂载点使用情况、大文件TOP5
- 进程：进程列表(PID/名称/CPU/内存)，可点击结束进程

**数据更新**：
- 更新频率：2秒一次（可在设置调整为1s/5s）
- 只在容器Tab可见时采集，不可见时暂停（节省资源）
- 命令合并执行：`cat /proc/stat && cat /proc/meminfo && df && ps`，减少进程创建

## 四、内置浏览器深化

### 4.1 现状分析

浏览器位于 `feature/browser/`，v0.0.0.19完成了UI重构（标签栏顶部、地址栏、底部工具栏）和反检测增强（stealth脚本、role+name定位、actionability检查、鼠标轨迹模拟）。

### 4.3 功能点详细设计

#### F4.1 AI网页摘要效果调优

**摘要质量提升**：
- **正文提取优化**：
  - 排除导航栏、页脚、广告（基于语义标签`<nav><footer><aside>`和常见CSS类名黑名单）
  - 基于文本密度判断正文区域（文字占比高的区域）
  - 长文章自动分段，每段独立提取
- **摘要生成**：
  - 短文章(<500字)：直接返回全文，不做摘要
  - 中等文章(500-3000字)：3-5句核心摘要
  - 长文章(>3000字)：分段摘要 + 总体摘要 + 关键要点
- **输出格式**：
  - 标题（如果页面有明确标题）
  - 核心观点（3条bullet）
  - 详细摘要（段落）
  - 关键数据（表格，如有数字/统计）
  - 相关链接（页面中的重要外链）

**结构化提取增强**：
| 页面类型 | 提取字段 |
|----------|----------|
| 文章页 | 标题、作者、发布时间、正文、标签、配图、阅读时长 |
| 产品页 | 名称、价格、评分、评论数、描述、规格参数、图片、库存 |
| 搜索结果 | 结果列表（标题、URL、摘要、排名、来源） |
| 论坛帖 | 标题、楼主、回复数、时间、正文、热门回复(前5) |
| 视频页 | 标题、UP主、播放量、发布时间、简介、评论数 |
| 通用页 | 标题、URL、meta描述、主要内容文本 |

**页面类型自动识别**：
- 基于URL模式（如 `/product/`、`/article/`、`/search?`）
- 基于DOM结构（产品页有价格元素、搜索页有结果列表）
- 基于meta标签（`og:type`）
- 识别失败时降级为「通用页」

**提取失败降级**：
- 结构化提取失败 → 自动降级为全文摘要
- 全文摘要也失败 → 返回页面纯文本 + 失败原因说明
- 失败时记录日志，便于后续优化

#### F4.2 多标签页管理优化

**标签管理面板**：
- 入口：标签栏右侧「标签数」按钮（如「12」）
- 面板：从底部滑出的BottomSheet，占屏幕80%高度
- 网格布局：2列，每个标签卡片：
  - favicon(16dp) + 标题(14sp，截断1行)
  - URL(12sp onSurfaceVariant，截断1行)
  - 缩略图（页面截图，可选，P2）
  - 关闭按钮（右上角）
- 面板顶部：搜索框 + 「关闭其他」「关闭全部」按钮
- 最近关闭：面板底部显示最近关闭的5个标签，可点击恢复

**标签分组**（P2）：
- 长按标签 → 「创建分组」→ 输入分组名称 + 选择颜色
- 分组在标签栏显示为一个组标签（颜色标记+组名）
- 点击组标签展开/折叠组内标签
- 分组可重命名、改色、删除（删除组不删除标签）

**标签搜索**：
- 标签管理面板顶部搜索框
- 按标题/URL模糊搜索
- 搜索结果实时过滤

#### F4.3 下载管理完善

**下载面板**：
- 入口：底部工具栏「下载」按钮（或更多菜单）
- 面板：BottomSheet，占屏幕70%高度
- 列表按状态分组：下载中 / 已完成 / 失败

**下载中项**：
- 文件图标 + 文件名(14sp) + 大小(12sp)
- 进度条（高度4dp，`primary`色）+ 百分比(12sp)
- 下载速度(12sp onSurfaceVariant，如「2.3 MB/s」)
- 操作：暂停/继续按钮、取消按钮

**已完成项**：
- 文件图标 + 文件名 + 大小 + 完成时间
- 操作：打开（用对应应用）、分享、删除、查看所在目录

**失败项**：
- 文件图标 + 文件名 + 错误原因(12sp error色)
- 操作：重试、删除

**下载设置**：
- 下载位置：默认 `Download/MiniMeBrowser/`，可更改
- 仅WiFi下载：开关（默认关）
- 下载完成通知：开关（默认开）
- 并发下载数：1-3（默认2）
- 大文件警告：>50MB时确认（默认开）

**下载拦截**：
- WebView检测到下载请求时，弹出确认对话框
- 显示：文件名、大小、来源URL、文件类型
- 按钮：下载 / 取消
- 大文件额外警告存储空间

#### F4.4 书签与历史搜索分类

**书签管理**：
- 书签文件夹：支持多级文件夹（最多3级）
- 新建书签：可选择文件夹、添加标签
- 书签搜索：顶部搜索框，按标题/URL/标签搜索

- 书签网格/列表视图切换

**历史管理**：
- 历史搜索：顶部搜索框，按标题/URL搜索
- 按站点分组：同一域名的历史合并显示（可展开）

- 批量删除：长按进入多选，可按时间范围删除
- 左滑删除：单条历史左滑显示删除按钮

#### F4.5 网页内容与AI整合

**划词提问**：
- 在网页中长按选中文字，系统菜单增加「问AI」选项
- 点击后：
  1. 跳转到AI对话页（或底部弹出AI面板）
  2. 自动填入：「关于网页内容的问题：{选中文字}」
  3. 同时将当前页面URL和选中上下文（前后各200字）作为参考信息
- AI回答时可引用网页原文段落

**页面总结入口**：
- 底部工具栏AI助手面板增加「总结当前页面」按钮
- 点击后：AI自动调用view动作提取页面内容并生成摘要
- 摘要显示在AI面板内，可继续追问
- 摘要可复制、可收藏

**AI面板网页参考**：
- AI操作浏览器时，面板显示当前页面关键信息：
  - 页面标题 + favicon
  - URL（截断显示）
  - 加载状态（加载中/完成/失败）
- AI提取的结构化内容在面板内预览（可折叠/展开）
- AI执行的操作历史时间线（已有，增强显示）

**AI自动浏览**：
- 用户输入「帮我查找XX信息」，AI自动：
  1. 打开搜索引擎
  2. 搜索关键词
  3. 浏览搜索结果
  4. 提取相关信息
  5. 汇总回答
- 过程中用户可随时接管（已有takeover功能）

#### F4.6 阅读模式（新增）

**设计**：文章类网页提供阅读模式，去除广告和干扰元素。

- **触发条件**：
  - 检测到文章页（有大段正文、标题、作者信息）
  - 地址栏显示「阅读模式」图标（书本图标）
  - 用户点击图标进入阅读模式
- **阅读模式效果**：
  - 去除：导航栏、侧边栏、广告、评论区、推荐内容
  - 保留：标题、作者、发布时间、正文、正文图片
  - 排版优化：行宽限制(600dp)、行高1.8、字号16sp、段间距16dp
- **阅读模式设置**：
  - 字号：小/中/大/超大（14-22sp）
  - 主题：浅色/深色/护眼(米黄)
  - 字体：衬线/无衬线
  - 亮度调节
- **朗读功能**（P2）：
  - 阅读模式底部增加「朗读」按钮
  - 使用系统TTS朗读正文
  - 可调节语速、音色
  - 朗读时高亮当前句子

**实现**：
- 使用Readability算法提取正文（JavaScript注入WebView执行）
- 提取后用原生Composable重新渲染正文（非WebView）
- 图片懒加载，点击可放大

#### F4.7 网页翻译（新增）

**设计**：一键翻译网页内容。

- **触发方式**：

**导入验证**：
- 格式校验：JSON格式正确、版本兼容

## 六、性能与稳定性

### 6.1 现状分析

项目采用Compose + Hilt + Coroutines，SQLDelight数据库，PRoot容器。目前无系统性的性能监控和优化。

**已知问题与优化空间**：
- 冷启动时间未测量，启动动画6秒可能掩盖了实际初始化耗时
- 内存泄漏风险（单例持有Context、协程未取消、Flow未正确收集）
- 长列表（对话历史、设置项）渲染性能未优化
- 崩溃仅靠系统报告，无应用内捕获和上报
- 数据库查询未优化，大数量下可能卡顿
- 无ANR监控
- 无网络请求监控
- 电池优化未考虑

### 6.2 优化目标

1. 启动速度：冷启动时间可测量、可优化，目标<2秒（不含动画）
2. 内存健康：无明显泄漏，峰值内存可控，OOM率<0.1%
3. 渲染流畅：长列表60fps，无明显掉帧，卡顿率<1%
4. 崩溃治理：应用内捕获、自动上报、可追溯，崩溃率<0.5%
5. 数据库优化：查询响应<50ms，无ANR
6. 电池友好：后台耗电<5%/小时

### 6.3 功能点详细设计

#### F6.1 冷启动速度优化与测量

**启动耗时测量**：
- 在 `MiniMeCore.onCreate` 开始记录时间戳（`System.nanoTime()`）
- 关键节点打点：
  | 节点 | 标记 | 说明 |
  |------|------|------|
  | T0 | attachBaseContext | 应用创建开始 |
  | T1 | onCreate开始 | Application创建 |
  | T2 | Hilt注入完成 | 依赖注入 |
  | T3 | 数据库初始化 | 数据库打开+migration |
  | T4 | 主题加载 | 从KVStore读取主题设置 |
  | T5 | MainActivity.onCreate | Activity创建 |
  | T6 | 首帧渲染 | 第一帧绘制完成 |
  | T7 | 首屏数据加载 | 首屏所需数据加载完成 |
  | T8 | 可交互 | 用户可正常操作 |
- 启动完成后输出耗时日志：各阶段耗时 + 总耗时
- 开发者选项内可视化：柱状图显示各阶段占比

**初始化优化**：
- **延迟初始化**：
  - 不影响首屏的初始化移到首帧渲染后（MCP连接、终端保活、浏览器预热）
  - 使用 `by lazy` 懒加载单例
  - 非核心服务用 `Dispatchers.IO` 异步初始化
- **并行初始化**：
  - 无依赖的初始化任务并行执行（数据库、主题、网络）
  - 使用 `CoroutineScope.async` 并行，`await` 汇总
- **数据库优化**：
  - SQLDelight查询添加索引（常用查询字段）
  - 启动时不预加载全部数据，按需查询
  - 大表查询分页（LIMIT/OFFSET）
- **首屏优化**：
  - 首屏显示骨架屏，数据异步加载
  - 图片懒加载，首屏不加载非可见图片
  - 预测量：在动画期间完成首屏测量和布局

**目标**：
- 中端机冷启动（T0→T8）< 2秒（不含启动动画）
- 低端机 < 3秒
- 各阶段耗时占比：Hilt<20%，数据库<15%，首屏渲染<30%

#### F6.2 内存泄漏排查与预防

**泄漏检测集成**：
- Debug构建集成 LeakCanary（`debugImplementation`，release不包含）
- 应用退出（Activity销毁）时自动分析内存
- 发现泄漏输出报告：泄漏对象、引用链、建议修复
- 泄漏报告保存到本地文件，可在开发者选项查看

**常见泄漏点修复**：
| 泄漏类型 | 修复方案 |
|----------|----------|
| 单例持有Activity | 改用ApplicationContext或弱引用 |
| 协程未取消 | ViewModel.onCleared中取消，使用viewModelScope |
| Flow未正确收集 | 使用collectAsStateWithLifecycle（生命周期感知） |
| BroadcastReceiver未注销 | onDestroy中注销 |
| 监听器/回调未移除 | 对应生命周期移除 |
| WebView未销毁 | Activity.onDestroy中调用destroy并从父布局移除 |
| 静态View引用 | 不使用静态变量持有View |
| 匿名内部类持有外部 | 改为静态内部类+弱引用 |

**内存监控**：
- 开发者选项显示当前内存使用：
  - Java堆：已用/最大值
  - Native堆：已用/最大值
  - 图形内存：已用
  - 其他：系统/代码/栈
- 内存超过阈值(80%)时显示警告（通知栏+开发者选项）
- 内存使用历史曲线（最近30分钟，2秒采样一次）
- OOM时自动捕获内存快照（hprof文件，仅debug）

**内存优化**：
- 图片缓存：使用LRU缓存，最大内存的1/8
- 长列表：不可见的图片回收，消息内容压缩
- 大对象：及时释放（如WebView销毁、数据库游标关闭）
- 避免内存抖动：循环中不创建临时对象

#### F6.3 长列表渲染性能

**对话列表优化**：
- `LazyColumn` + `items` 的稳定key（消息ID，非index）
- 消息内容使用 `remember` 缓存解析结果（Markdown解析只做一次）
- 长消息折叠：超过500字默认折叠，点击展开（减少初始渲染量）
- 图片消息懒加载：使用 `Coil`，仅可见时加载，不可见时取消
- 消息气泡使用 `SubcomposeLayout` 预测量，避免动态高度跳动
- 代码块懒渲染：超过100行只渲染可见区域

**设置列表优化**：
- 分组使用 `stickyHeader`，滚动时标题固定在顶部
- 设置项使用 `remember` 缓存状态（开关状态、当前值）
- 大量设置项(>50)使用 `LazyColumn`，非全部渲染

**通用优化**：
- 避免在 `items` 的 itemContent 中做耗时操作（解析、计算）
- 使用 `Modifier.animateItem()` 做插入/删除动画（可选，性能影响小可开启）
- 列表滚动时暂停非关键动画（头像脉冲、加载动画）
- 使用 `derivedStateOf` 避免不必要的重组（如滚动位置计算）

**性能目标**：
- 1000条消息的对话滚动帧率 ≥ 55fps
- 100个设置项的列表滚动帧率 ≥ 58fps
- 新消息插入动画无卡顿

#### F6.4 崩溃捕获与上报

**应用内崩溃捕获**：
- 集成 `Thread.setDefaultUncaughtExceptionHandler`
- 崩溃时保存崩溃信息到本地文件（加密存储）
- 崩溃后下次启动显示「上次崩溃」对话框

**崩溃信息内容**：
- 崩溃堆栈（完整，包含所有线程）
- 设备信息：型号、品牌、Android版本、SDK版本、内存、存储、屏幕分辨率
- 应用信息：版本号、构建号、构建类型、安装时间
- 应用状态：当前页面、最近操作（最近20条用户操作日志）、内存使用、存储剩余
- 发生时间、进程ID、线程ID

**上报机制**：
- 用户可选择「自动上报」或「每次询问」或「不报告」
- 上报到配置的端点（预留接口，当前可配置为自定义URL）
- 上报失败时保留本地，下次启动重试（最多3次）
- 上报内容用户可查看（透明化）

**崩溃统计**：
- 开发者选项显示崩溃历史（最近10条）
- 按崩溃类型分组统计（相同堆栈的合并）
- 崩溃趋势图（最近7天崩溃次数）
- 可导出崩溃日志为文件（分享给开发者）

**ANR监控**：
- 监听主线程阻塞：使用 `Choreographer` 检测帧丢失
- 帧丢失超过3秒（约180帧）判定为ANR风险
- ANR发生时收集主线程堆栈和所有线程状态
- ANR信息与崩溃信息统一管理

#### F6.5 数据库性能优化

**索引优化**：
| 表 | 索引 | 查询场景 |
|----|------|----------|
| 消息表 | (session_id, timestamp) 联合索引 | 按会话查询消息列表 |
| 消息表 | (session_id, role) | 按角色统计 |
| 会话表 | (updated_at) | 会话列表排序 |
| 历史记录表 | (url, timestamp) | 按URL和时间查询 |
| 书签表 | (created_at) | 书签列表排序 |
| 设置变更表 | (timestamp) | 变更历史查询 |

**查询优化**：
- 列表查询使用 `LIMIT` + `OFFSET` 分页（每页50条）
- 计数查询使用 `COUNT(*)`，不加载全部数据
- 复杂查询预编译（SQLDelight自动处理）
- 避免N+1查询：使用JOIN一次查询关联数据

**写入优化**：
- 批量插入使用事务（`transaction`），减少磁盘IO
- 频繁写入的表使用WAL模式（SQLDelight配置）
- 非关键写入异步执行（不阻塞UI）
- 写入后延迟更新UI（合并多次写入为一次UI更新）

**数据库维护**：
- 定期清理过期数据：
  - 浏览历史：30天前自动清理（可配置）
  - 下载记录：30天前自动清理
  - 崩溃日志：10条以上清理最旧的
  - 设置变更历史：100条以上清理最旧的
- 提供「清理缓存」功能：
  - 清除图片缓存
  - 清除网络缓存
  - 清除临时文件
  - 清除搜索历史
  - 显示各缓存大小，可选择性清理
- 数据库VACUUM：定期执行（每月一次，应用空闲时），减少碎片

#### F6.6 网络请求监控（新增）

**设计**：监控所有HTTP请求，用于调试和性能分析。

- **监控内容**：
  - 请求：URL、方法、请求头、请求体大小、发起时间
  - 响应：状态码、响应头、响应体大小、耗时
  - 错误：错误类型、错误信息
- **展示**：
  - 开发者选项 → 网络监控
  - 列表：按时间倒序，每项显示方法+URL+状态码+耗时
  - 点击查看详情：请求/响应完整信息
  - 过滤：按状态码、按域名、按耗时
- **统计**：
  - 请求总数、成功率、平均耗时
  - 最慢的10个请求
  - 失败请求列表
- **限制**：仅debug构建启用，release不记录（隐私和性能考虑）

#### F6.7 电池优化（新增）

**设计**：减少应用后台耗电。

- **后台限制**：
  - 应用退到后台5分钟后，暂停非必要后台任务
  - 终端保活服务：用户可配置（始终/仅充电时/从不）
  - 容器运行：后台时降低CPU优先级
- **网络优化**：
  - 后台时减少轮询频率（如从30s改为5min）
  - 批量网络请求，减少唤醒次数
  - 使用 `WorkManager` 调度延迟任务
- **唤醒控制**：
  - 不使用 `WAKE_LOCK`（除非用户明确要求终端保持运行）
  - 下载使用 `DownloadManager`（系统优化）
- **电池使用统计**：
  - 开发者选项显示应用耗电估算
  - 各模块耗电占比（终端/网络/CPU/屏幕）

## 十一、风险评估与回滚方案

### 11.1 技术风险

| 风险 | 影响 | 概率 | 缓解措施 |
|------|------|------|----------|
| Markdown渲染器边界case多 | 部分Markdown显示异常 | 中 | 先实现核心元素，逐步完善；充分测试 |
| 容器文件管理器特殊文件名解析失败 | 文件操作失败 | 中 | 使用find命令替代ls解析；异常处理完善 |
| 终端分屏Termux库不支持多实例 | 分屏功能无法实现 | 低 | 提前验证；备选方案为多标签不分屏 |
| 阅读模式正文提取准确率不稳定 | 部分网页提取失败 | 高 | 失败时回退到原网页；持续优化提取算法 |
| 崩溃上报可能收集敏感信息 | 隐私风险 | 中 | 默认不自动上报；用户可查看内容；不收集对话内容 |
| 数据库migration失败 | 升级后数据丢失 | 低 | migration前自动备份；提供恢复机制 |
| LeakCanary增加debug构建体积 | debug包变大 | 低 | 仅debugImplementation，release不包含 |

### 11.2 性能风险

| 风险 | 影响 | 缓解措施 |
|------|------|----------|
| 新功能增加冷启动时间 | 启动变慢 | 延迟初始化非核心功能；启动测量监控 |
| Markdown渲染增加消息列表负担 | 长对话卡顿 | 解析结果缓存；长消息折叠；懒渲染 |
| 资源监控增加CPU占用 | 终端性能下降 | 仅可见时采集；2秒间隔；命令合并执行 |
| 密码管理器增加内存占用 | 内存增加 | 密码库按需加载；使用后及时清理 |

### 11.3 回滚方案

- **功能级回滚**：每个新功能通过Feature Flag控制，发现问题可远程关闭
- **版本级回滚**：保留前一版本APK，引导用户降级
- **数据级回滚**：数据库migration前自动备份，失败时恢复
- **设置级回滚**：设置变更历史支持回滚到任意时间点

### 11.4 依赖关系图

```
F2.1 Markdown渲染 → F2.3 消息操作(复制代码) → F2.8 对话导出
F3.1 文件管理器 → F3.5 文件互传
F4.1 摘要调优 → F4.5 AI整合 → F4.6 阅读模式(摘要)
F5.2 导出导入 → F5.3 变更历史(回滚需要备份)
F6.1 启动测量 → F1.7 初始化进度(数据来源)
F6.4 崩溃捕获 → F5.6 开发者选项(崩溃查看)
```
