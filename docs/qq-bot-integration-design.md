# MiniMe-core QQ 机器人对接设计文档

> 版本：v1.1
> 状态：设计阶段
> 最后更新：2026-09-27

## 一、概述

### 1.1 项目目标

将 MiniMe-core 的 AI Agent 能力与 QQ 平台对接，使 Agent 可以作为 QQ 机器人运行，接收 QQ 消息并通过 AI 生成回复。

### 1.2 核心思路

采用 **方案 A：MiniMe-core 内置 OneBot 11 反向 WebSocket 服务端 + 终端容器内运行 LLBot**。

```
QQ 用户 → LLBot（协议端，无头模式）→ OneBot 11 反向 WS → MiniMe-core Agent → 回复 → LLBot → QQ
```

### 1.3 技术选型

| 组件 | 选型 | 说明 |
|------|------|------|
| 协议端 | LLBot（LuckyLilliaBot）无头模式 | 纯协议实现，不依赖 QQ 客户端，Rust 编写，Linux arm64 可运行 |
| 通信协议 | OneBot 11（反向 WebSocket） | 生态最成熟，功能最全，兼容 GoCQ |
| Agent 核心 | MiniMe-core 现有 Agent | 复用已有对话、工具、模型能力 |
| WS 服务端 | Ktor / OkHttp WebSocket | 监听本地回环端口 |
| 运行环境 | MiniMe-core 终端容器（Proot/Linux） | LLBot 在容器内运行，用户无感 |
| 进程保活 | Android Foreground Service + Watchdog | 前台服务常驻 + 进程守护自动重启 |

## 二、可行性分析

### 2.1 LLBot 在 Android 容器内运行

| 维度 | 可行性 | 说明 |
|------|--------|------|
| Node.js 运行时 | 可行 | 容器内可安装 Node.js，LLBot CLI 版基于 Node.js |
| Rust 纯协议版 | 可行 | LLBot 无头模式为 Rust 实现，提供 Linux arm64 二进制 |
| PMHQ 有头模式 | 不可行 | 需要 NTQQ 客户端，Android 容器内无法运行桌面 QQ |
| 网络 | 可行 | 容器共享主机网络，本地回环通信无延迟 |
| 文件系统 | 可行 | 容器内可读写，图片/语音缓存有存储位置 |
| 后台保活 | 已解决 | 前台服务 + 进程守护 + WakeLock，详见第六章 |
| 内存占用 | 可接受 | LLBot 约 100-200MB，Agent 约 300MB，合计 500MB+ |

**结论**：使用**无头模式（纯协议 Rust 版）**，轻量稳定，不依赖 QQ 客户端。

### 2.2 OneBot 11 反向 WS 服务端

MiniMe-core 为 Kotlin/Compose 应用，内置 WebSocket 服务端无技术障碍：
- 监听本地端口（默认 3001）
- LLBot 配置反向 WS 指向 `ws://127.0.0.1:3001`
- 纯本地通信，不涉及公网暴露
- 复用项目已有网络层基础

### 3.2 核心模块

| 模块 | 职责 |
|------|------|
| QBotService | 前台服务，管理 LLBot 进程生命周期 + WebSocket 服务端 + 通知栏 |
| LLBotProcessManager | 启动/停止/重启 LLBot，存活检测，异常自动重启，日志采集 |
| ContainerBridge | 封装容器执行命令，文件读写，端口检测（用户不可见） |

| QBotActivity | 独立管理页面，用户唯一操作入口 |

## 四、消息流设计

### 4.1 接收消息流

```
LLBot 收到 QQ 消息
  → 反向 WS 推送给 MiniMe-core（JSON）
  → OneBot11Server 解析协议
  → MessageMapper 转换消息格式
  → TriggerEngine 判断是否触发
  → SessionManager 获取/创建会话
  → Agent 调度器调用 agent.chat()
  → 等待 AI 回复
  → ReplyFormatter 格式化回复
  → OneBot11Server 调用 send_group_msg / send_private_msg
  → LLBot 发送到 QQ
```

### 4.2 消息格式转换

#### OneBot → Agent（输入）

| OneBot 消息段 | Agent 消息 | 处理方式 |
|--------------|-----------|---------|
| text | 文本 | 直接传递 |
| image | 图片 | 下载到本地缓存，作为多模态输入 |
| at | @提及 | 过滤@机器人部分，保留@其他人 |
| reply | 引用回复 | 提取被引用消息作为上下文 |
| face | QQ表情 | 转为文字描述或忽略 |
| record | 语音 | 暂不支持（后续可加语音识别） |
| video | 视频 | 暂不支持 |

#### Agent → OneBot（输出）

| Agent 输出 | OneBot 消息段 | 处理方式 |
|-----------|--------------|---------|
| 文本 | text | 直接发送，超长自动分段 |
| 图片 | image | 上传到 QQ（LLBot 处理） |
| 代码块 | text | 保留代码格式 |
| Markdown | text | 转为纯文本 |
| 工具调用结果 | text | 格式化后发送 |

## 六、无感容器运行与进程持久化

### 6.1 设计原则

- **用户永远看不到终端**：不需要知道 LLBot 跑在容器里
- **QBot 管理页面是唯一操作入口**：所有容器操作封装在后台服务
- **进程不可无故死亡**：多层保活，异常自动恢复

### 6.2 用户操作映射

| 用户在页面操作 | 后台实际执行 | 用户看到的 |
|--------------|------------|-----------|
| 点击"启动" | ContainerBridge 执行 LLBot 启动命令 → 等待端口就绪 | 状态：停止中 → 启动中 → 运行中 |
| 点击"停止" | 发送 SIGTERM → 等待进程退出 | 状态变为"已停止" |
| 点击"扫码登录" | 读取 LLBot 输出的二维码 → 渲染到页面 | 页面显示二维码，扫码后状态更新 |
| 查看日志 | 从内存环形缓冲读取最近 N 行 | 页面显示日志列表，自动滚动 |
| 修改配置 | 写入配置文件 → 运行中提示重启生效 | 保存成功提示 |

### 6.3 多层保活架构

```
第1层：前台服务（Foreground Service）
  └─ QBotService 以 startForeground 启动，常驻通知栏
  └─ 通知栏显示："QBot 运行中 · QQ: 123456 · 点击管理"
  └─ 优先级：IMPORTANCE_FOREGROUND（系统最后才会杀）

第2层：进程守护（Watchdog）
  └─ QBotService 内独立线程，每 5 秒检测 LLBot 进程存活
  └─ 检测方式：容器内 ps 检查 + 端口 3001 连通性检测
  └─ 进程死亡 → 自动重启（退避：1s→2s→5s→10s→30s，最多重试 5 次）
  └─ 重启失败 → 通知栏告警 + 页面显示异常状态

第3层：系统唤醒（WakeLock + WifiLock）
  └─ PARTIAL_WAKE_LOCK：防止 CPU 休眠导致 WS 断开
  └─ WIFI_MODE_FULL_HIGH_PERF：防止 WiFi 休眠断连
  └─ 仅在 QBot 运行时持有，停止时释放

第4层：开机自启（Boot Receiver）—— 第二阶段实现
  └─ 监听 BOOT_COMPLETED
  └─ 如用户开启"开机自启"，自动启动 QBotService

第5层：应用重启恢复
  └─ QBotService 在 onStartCommand 返回 START_STICKY
  └─ 应用被系统杀死后自动重建，恢复 QBot 状态
```

### 6.4 进程状态机

```
                    ┌──────────┐
                    │  未启动   │
                    └────┬─────┘
                         │ 用户点击启动
                    ┌────▼─────┐
              ┌────►│  启动中   │◄────┐
              │     └────┬─────┘     │
              │          │ 端口就绪   │ 自动重试
              │     ┌────▼─────┐     │
              │     │  运行中   │     │
              │     └────┬─────┘     │
              │          │ 进程死亡   │
              │     ┌────▼─────┐     │
              │     │  异常中   │─────┘
              │     └────┬─────┘
              │          │ 重试耗尽
              │     ┌────▼─────┐
              │     │  已停止   │
              │     └──────────┘
              │
              └─ 用户点击停止 → 已停止
```

### 6.5 异常处理策略

| 异常场景 | 检测方式 | 处理 |
|---------|---------|------|
| LLBot 进程崩溃 | ps 检测不到进程 | 自动重启，退避策略 |
| WS 连接断开 | LLBot 反向 WS 断连 | 等待 LLBot 重连（LLBot 自带重连） |
| 端口被占用 | 启动时检测 3001 | 提示端口冲突，可换端口 |
| 容器环境损坏 | 启动命令执行失败 | 提示重新初始化容器 |
| QQ 掉线 | LLBot 日志输出掉线 | 页面显示"QQ已掉线"，提示重新登录 |
| 内存不足 | 系统 onLowMemory | 释放非必要缓存，通知用户 |

### 6.6 通知栏设计

```
┌─────────────────────────────────┐
│  QBot 运行中                     │
│  QQ: 123456789 · 已连接          │
│  今日消息: 42                    │
│  [停止]  [管理]                  │
└─────────────────────────────────┘
```
- 点击通知 → 打开 QBot 管理页
- "停止"按钮 → 直接停止 QBot
- 常驻通知，不可滑动删除（前台服务特性）

## 八、权限与安全

### 8.1 用户角色层级

| 角色 | 说明 | 能力 |
|------|------|------|
| 主人 | 配置的 QQ 号 | 全部权限 |
| 管理员 | 群管理员 / 自定义 | 禁言、踢人、审批、配置、切换模型 |
| 信任用户 | 自定义 | 可使用 agent 工具（终端/浏览器/MCP） |
| 普通成员 | 默认 | 基础 agent 对话 |
| 受限用户 | 自定义 | 只能触发关键词回复，不能 agent 对话 |
| 黑名单 | 自定义 | 完全忽略 |

### 8.2 工具调用安全（核心）

**默认原则：QQ 机器人仅开放纯对话能力，工具调用需显式授权。**

| 工具 | 风险 | 默认权限 | 可授权给 |
|------|------|---------|---------|
| 终端命令执行 | 任意用户可控制手机终端 | 禁用 | 信任用户+ |
| 浏览器 | 访问内网、消耗流量 | 禁用 | 信任用户+ |
| MCP 工具 | 取决于具体 MCP 服务 | 禁用 | 按工具粒度配置 |
| 文件操作 | 读写手机文件 | 禁用 | 管理员+ |
| 代码执行 | 执行任意代码 | 禁用 | 管理员+ |

### 8.3 防滥用机制

- 速率限制：每用户每分钟最多 N 条消息（默认 10 条）
- 并发限制：同时最多 N 个会话在生成（默认 3 个）
- 内容过滤：敏感词过滤（可选）
- 日志审计：所有 QQ 消息和回复记录日志

## 十、QQ 群管理功能

| 禁言 | `set_group_ban` | 禁言/解禁，可设时长 |
| 全员禁言 | `set_group_whole_ban` | 开启/关闭全员禁言 |
| 踢人 | `set_group_kick` | 移出群成员，可选拒绝再加群 |
| 群名片 | `set_group_card` | 修改成员群昵称 |
| 管理员设置 | `set_group_admin` | 设置/取消管理员 |

### 10.2 每群独立配置

每个群存储独立配置（GroupConfig）：

```
GroupConfig
├── 基础设置：群名缓存、机器人昵称、启用/禁用、欢迎消息
├── 触发规则：触发方式、关键词前缀、忽略关键词
├── 模型配置：默认模型、上下文长度、群专属系统提示词、参数
├── 权限配置：工具可用角色、触发角色、黑名单
├── 群管理：自动审批、自动欢迎、违禁词检测、刷屏检测、定时消息
└── 数据统计：消息数、响应数、活跃用户
```

### 10.3 群自动化功能

#### 新成员欢迎
- 触发：`group_increase` 事件
- 可配置欢迎语模板（支持 `{user_name}` `{group_name}` 变量）
- 可选 @新成员、发送群规

#### 加群自动审批
- 策略：自动通过 / 匹配关键词通过 / 自动拒绝 / 手动审批
- 手动审批：转发管理员，回复"通过"/"拒绝"
- 记录审批日志

#### 违禁词检测
- 内置词库 + 自定义词库 + 正则匹配
- 处理方式：仅警告 / 撤回 / 禁言（时长可配） / 踢人 / 通知管理员

#### 刷屏检测
- 检测维度：短时间消息数、重复消息、长文本
- 惩罚梯度：警告 → 禁言10分钟 → 禁言1小时

#### 定时消息
- 支持每天/每周/每月/间隔周期
- 内容：文本/图片/混合
- 可配置目标群（单个或多个）

#### 关键词自动回复
- 触发：精确匹配 / 模糊匹配 / 正则
- 回复：文本/图片/混合
- 支持优先级排序

### 10.4 群权限矩阵

| 操作 | 群主 | 管理员 | 信任用户 | 普通成员 | 受限 |
|------|------|--------|---------|---------|------|
| agent 对话 | ✓ | ✓ | ✓ | ✓ | ✗ |
| 工具调用 | ✓ | ✓ | ✓ | ✗ | ✗ |
| 切换模型 | ✓ | ✓ | ✗ | ✗ | ✗ |
| 禁言/踢人 | ✓ | ✓ | ✗ | ✗ | ✗ |
| 修改群配置 | ✓ | ✓ | ✗ | ✗ | ✗ |
| 加群审批 | ✓ | ✓ | ✗ | ✗ | ✗ |
| 查看统计 | ✓ | ✓ | ✗ | ✗ | ✗ |

### 10.5 群管理指令

| 指令 | 功能 | 权限 |
|------|------|------|
| `/信任 @用户` | 设为信任用户 | 管理员+ |
| `/受限 @用户` | 设为受限 | 管理员+ |
| `/拉黑 @用户` | 加入黑名单 | 管理员+ |
| `/解禁 @用户` | 移除黑名单 | 管理员+ |
| `/禁言 @用户 10m` | 禁言指定时长 | 管理员+ |
| `/踢人 @用户` | 移出群 | 管理员+ |
| `/统计` | 查看群统计 | 管理员+ |
| `/排行` | 活跃用户排行 | 管理员+ |

### 10.6 与 Agent 协同

- **Agent 辅助管理**：自然语言指令，如"把刚才发广告的人禁言10分钟"
- **智能群规**：Agent 判断消息是否违规，给出处理建议
- **自动群聊总结**：每日自动生成群聊摘要
- **问答知识库**：常见问题自动回复，不消耗 agent 调用

## 十二、阶段划分与实施路线

### 12.1 阶段总览

| 阶段 | 目标 | 核心交付 |
|------|------|---------|
| **第一阶段** | 机器人可登录 + 简单回复可用 | 能在 QQ 上和 Agent 对话 |
| 第二阶段 | 群聊完善 + 权限体系 | 群聊@触发、黑白名单、图片消息、开机自启 |
| 第三阶段 | LLBot 深度集成 | 外部 LLBot 模式、配置热重载、一键下载更新 |
| 第四阶段 | 群管理自动化 | 欢迎、审批、禁言踢人、违禁词、定时消息、群统计 |
| 第五阶段 | 高级功能 + 生态 | 工具调用授权、多QQ号、Satori协议、Agent辅助管理 |

### 12.2 第一阶段详细范围

#### 目标
用户在 MiniMe-core 内配置 QQ 号 → LLBot 登录 → QQ 私聊/群聊@机器人 → Agent 回复文本

#### 包含功能

| 模块 | 功能 | 说明 |
|------|------|------|
| QBot 独立页面 | 管理页 UI | 与浏览器同级的独立页面，用户唯一入口 |
| QBotService | 前台服务 | 进程持久化基础，通知栏常驻 |
| LLBotProcessManager | 进程管理 | 启动/停止/状态监控/自动重启/日志采集 |
| ContainerBridge | 容器桥接 | 封装容器操作，用户无感 |
| OneBot11Server | WS 服务端 | 监听 3001 端口，接收消息，发送回复 |
| 消息处理 | 文本消息 | 私聊直接触发，群聊@触发，纯文本回复 |
| 会话管理 | 最简版 | 每用户独立会话，上下文20条，内存存储 |
| LLBot 集成 | 内置容器 | 检测/启动/停止，扫码登录，自动生成配置 |
| 基础日志 | 日志显示 | 内存环形缓冲500行，页面可查看 |
| 进程保活 | 多层防护 | 前台服务+Watchdog+WakeLock+START_STICKY |

#### 第一阶段不包含

- 图片/语音/视频消息
- 群管理功能（禁言/踢人/欢迎/审批）
- 权限体系（黑白名单/信任用户）
- 工具调用（终端/浏览器/MCP）
- 触发规则自定义（关键词/斜杠指令）
- 指令系统（/help /reset 等）
- 多 QQ 号
- 定时消息、违禁词检测
- 群统计、会话管理页面
- 开机自启
- 外部 LLBot 模式
- 配置热重载

#### 第一阶段技术要点

| 项 | 方案 |
|----|------|
| WS 服务端 | Ktor WebSocket Server 或 OkHttp |
| 端口 | 默认 3001，可配置 |
| 消息协议 | OneBot 11，messageFormat=array |
| Agent 调用 | 复用现有 Agent.chat() 接口 |
| 会话存储 | 内存 Map（第一阶段不持久化，重启清空） |
| LLBot 启动 | 通过 ContainerBridge 在终端容器执行命令 |
| 页面入口 | 独立 QBotActivity / Compose 页面，与浏览器同级 |

## 十三、风险与挑战

| 风险 | 严重度 | 应对措施 |
|------|--------|---------|
| Android 后台杀死 LLBot 进程 | 高 | 前台服务 + 通知栏常驻 + Watchdog 自动重启 |
| 国产 ROM 额外限制 | 中 | 引导用户关闭电池优化、加白名单 |
| QQ 封号风控 | 高 | 无头模式有风险，明确提示用户；限速限频 |
| 内存占用过大 | 中 | LLBot + Agent 合计 500MB+，低端机告警 |
| 工具调用安全 | 高 | 默认禁用工具，按用户角色授权 |
| 容器进程与服务进程隔离 | 中 | 用端口检测 + 日志文件作为状态同步 |
| LLBot 冷启动耗时 | 低 | 页面显示"启动中"，不阻塞 UI |
| 多容器实例冲突 | 低 | 启动前检测端口和进程，已有则不重复启动 |
